# 智慧办公室接口契约 v1

> 字段只增不改。样例见 [contracts/](contracts/)。  
> 原则：云端管交易、总控管放行、监控管感知、继电器只听总控。事件不是开门命令。

## 1. 职责矩阵

| 角色 | 可做 | 不可做 |
|------|------|--------|
| 云端 | 用户/预约/时长/券/生成授权单/暂存人脸照片/开门请求排队/站点策略 | 发继电器脉冲、存 embedding、判断人脸身份 |
| 总控 | 唯一软件开门、预取授权、策略放行、转发人脸入库、处理按钮开门、通知 | 改余额、核销券、存 embedding |
| 监控 | 录像/检测/比对/上报事实/质量门控后写入人脸库 | 调用继电器、持有开门 URL |
| 小程序 | 下单/核销/上传照片/请求开门 | 直连 ESP32、把支付成功显示成门已开 |
| ESP32ETH | 执行总控脉冲 | 接受其它来源命令 |
| 物理按钮 | 硬件回路开门 | — |

## 2. 关联号

`user_id` → `order_id` / `voucher_id` → `grant_id` → `command_id` → 总控门禁日志 → 云端回执。

所有跨系统消息必须带齐已有关联号；不可省略 `grant_id` / `command_id` 做幂等。

## 3. 身份与通道

| 身份 | 凭证 | 可调接口 |
|------|------|----------|
| 学员 | JWT（访问 2h，刷新 14d 轮换） | 云端学员 API |
| 店员 | 内网 HA TOTP | HA 面板 / 手工开门 / 停用人员 |
| 监控→总控 | HMAC 密钥 A | `POST /api/lobn_office/events` |
| 总控→云端 | HMAC 密钥 B | `GET /internal/grants/pending`、`POST /internal/grants/{id}/ack`、人脸状态回调、开门请求排队、站点配置 |
| 总控→监控 | HMAC 密钥 C | `POST /api/internal/persons/enroll` |
| 店员→总控 | HA 登录 | `POST /api/lobn_office/door/open`、本地人脸代录 `POST /api/lobn_office/face/enroll` |

三条服务密钥互不通用。学员 JWT 调用内部接口一律拒绝。

### HMAC 规则

- 算法：HMAC-SHA256，输出 hex。
- 头：`X-Lobn-Timestamp`（Unix 秒）、`X-Lobn-Nonce`（UUID）、`X-Lobn-Signature`。
- 签名串：`{timestamp}\n{nonce}\n{METHOD}\n{path}\n{sha256(body)}`。
- 时间窗：±60 秒。nonce 在 10 分钟内不可重放。

## 4. 消息 schema

### 4.1 监控 → 总控：`smartcctv.event.v1`

见 [contracts/smartcctv.event.v1.json](contracts/smartcctv.event.v1.json)。

- `type`：`face_known` | `face_unknown` | `zone_intrude` | `loiter` | `line_cross` | `crowd` | `door_request_manual`
- 本消息**不是**开门命令。总控收到后自行决策。
- 监控应对同一人、同一类事件合并后再上报。

### 4.2 总控 → ESP32：`door.command.v1`

见 [contracts/door.command.v1.json](contracts/door.command.v1.json)。

- `reason`：`face_match` | `booking_grant` | `manual`（预留 `token`）
- 只有总控发出。监控/云端/小程序不得持有 `open_url`。

### 4.3 云端 ↔ 总控：授权单

见 [contracts/grant.v1.json](contracts/grant.v1.json)。

回执 `result` 只允许：`opened` | `denied` | `unknown`。

## 5. 授权状态机与扣费

```
支付/时长券核销 → frozen → pending(生成 grant)
pending → opened   ：第一次成功脉冲，扣费一次
pending → denied   ：策略拒绝或过期，解冻
pending → unknown  ：继电器超时，保持冻结，不自动重扣、不连发
unknown → pending  ：店员确认后重试
```

- 窗口默认：预约开始前 10 分钟至结束（可在管理后台改）。窗口内可多次脉冲（冷却 30s），只在第一次 `opened` 扣费。
- 场次型团购券不自动退；时长型先入余额再冻结。
- 人脸开门不产生交易；人脸仅为窗口内可选便利，未录入也可小程序按钮开门（除非后台开启「必须人脸」）。

### 5.1 小程序按钮开门

```
学员 POST /api/door/request → 云端 DoorOpenRequest(pending)
总控轮询 GET /internal/door/requests/pending → open_by_grant → consume
```

### 5.2 人脸自动开门

监控上报 `face_known`（事实）→ 总控：人员在热名单且存在有效授权且 `face_auto_open` → 脉冲。  
无授权时只记 `face_sighting` 不开门。`face_unknown` 一律留痕（监控侧 30s 归并）。

## 6. 人脸录入状态

云端用户：`none` → `pending` → `accepted` | `rejected`。

- **通道 A（日常）**：小程序上传 → 云端暂存 JPEG/PNG（≤2MB，15 分钟）→ 总控拉取 → 监控质量门控入库。云端不存 embedding。
- **通道 B（断网/代录）**：店员经 HA `POST /api/lobn_office/face/enroll` 或监控本机页上传；图像不经云端，监控直接入库并写入总控热名单。
- `person.note` = 云端 `user_id` 字符串。

## 7. 降级表

| 依赖挂了 | 行为 |
|----------|------|
| 总控 | 所有软件开门停止；物理按钮可用；小程序显示门禁暂不可用 |
| 云端 | 已预取授权与已注册人脸继续；新订单/核销/录入失败 |
| 监控 | 预约与手工开门继续；人脸开门停止并通知店员 |
| 企业微信 | 开门不受影响；告警本地队列，>2h 普通告警丢弃 |
| 第三方核销 | 自建券可用；平台券返回暂不可用，不标已用 |

不可降：放行、脉冲、回执、审计。  
可暂停：通知、第三方核销、AI 管家、报表。暂停期间未开成的门不得自动补开。

## 8. 时钟

- 存储 UTC，界面 `Asia/Shanghai`。
- 总控 NTP 偏差 >2s：拒绝授权开门；已在窗口内的人脸仍受本地冷却约束。
- 授权单与总控时间差 >60s：拒绝。

## 9. 站点策略（云端可配）

管理后台 `/settings`：`button_open_enabled`、`face_auto_open`、`require_face_to_open`、`grant_window_lead_sec`、开放时段。  
总控经 `GET /internal/settings` 同步；`require_face_to_open` 仅约束小程序按钮（云端校验）。
