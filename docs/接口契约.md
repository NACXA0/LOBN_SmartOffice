# 智慧办公室接口契约 v1

> 字段只增不改。样例见 [contracts/](contracts/)。  
> 原则：云端管交易、总控管放行、监控管感知、继电器只听总控。事件不是开门命令。  
> **监控实现**：自研 SmartCCTV 已裁定归档，店内感知由 **HAOS + Frigate 插件**承担；总控仍是 SmartCenter（`lobn_office`）。说明见 [决策-归档自研SmartCCTV.md](决策-归档自研SmartCCTV.md)。下文含「监控 HMAC / smartcctv.event」的段落为**归档前契约**，接线改为 Frigate→HA 后另增 schema，旧样例留档不改义。

## 1. 职责矩阵

| 角色 | 可做 | 不可做 |
|------|------|--------|
| 云端（管理后台） | 用户/预约/时长/券/生成授权单/暂存人脸照片/开门请求排队/站点策略/告警收件箱与店员确认 | 发继电器脉冲、存 embedding、判断人脸身份、按告警自动开门或扣费、重做传感器抑制逻辑 |
| 总控（HA + lobn_office） | 唯一软件开门、预取授权、策略放行、传感器状态机、告警推送、通知、消费监控事实、与云端业务/统计 | 改余额、核销券、把店员确认当成开门；**不重做 NVR** |
| 监控（Frigate） | 录像/检测/区域/人脸库与识别/向 HA 提供事实 | 调用继电器、持有开门 URL、解释 PIR、承载预约交易 |
| 小程序 | 下单/核销/上传照片/请求开门 | 直连 ESP32、把支付成功显示成门已开 |
| ESP32-S3+W5500 | 执行总控脉冲、上报原始 sense | 接受其它来源命令、因 PIR/按钮/DHT 自行开门 |
| 门口按钮 / 人体红外 | 上报边沿，由总控决定是否结合监控做认证 | 硬件直连门锁、软件开门命令 |

谁处理了告警，必须用同一 `alert_id` 让另一方可见。总控自动抑制也算处理。

## 2. 关联号

`user_id` → `order_id` / `voucher_id` → `grant_id` → `command_id` → 总控门禁日志 → 云端回执。  
传感器告警另有 `alert_id`；sense 有 `event_id` 幂等。

所有跨系统消息必须带齐已有关联号；不可省略 `grant_id` / `command_id` 做幂等。

## 3. 身份与通道

| 身份 | 凭证 | 可调接口 |
|------|------|----------|
| 学员 | JWT（访问 2h，刷新 14d 轮换） | 云端学员 API |
| 店员 | 内网 HA TOTP / 管理后台店员 JWT | HA 面板；管理后台告警确认 |
| 监控→总控（归档前 · SmartCCTV） | HMAC 密钥 A | `POST /api/lobn_office/events` |
| 监控→总控（目标 · Frigate） | HA 集成 / MQTT 等（在 HA 进程内，不再经独立 CCTV HMAC 服务） | Frigate 事件由 `lobn_office` 订阅后决策 |
| 总控→云端 | HMAC 密钥 B | 授权/人脸/开门请求/站点配置/心跳/`POST /internal/alerts`/`GET /internal/alerts/pending-acks` |
| 总控→监控（归档前 · SmartCCTV） | HMAC 密钥 C | `POST /api/internal/persons/enroll`、`POST /api/internal/capture/assist`、通行采集 |
| 总控→监控（目标 · Frigate） | Frigate API / HA 服务（人脸库维护在 Frigate；业务 user 映射在总控） | 不再依赖 `cctv.lobn:8300` 自研口 |
| 总控→ESP | Bearer `esp_token` | `POST /v1/door/command`、`GET /v1/health` |
| ESP→总控 | 同一 Bearer | `POST /api/lobn_office/esp/sense` |
| 店员→总控 | HA 登录 | `POST /api/lobn_office/door/open`、业务相关面板 |

密钥 B 与 ESP Bearer 为现网主路径。A/C 仅在仍运行自研 SmartCCTV 的过渡期需要；归档完成后从部署清单移除。学员 JWT 调用内部接口一律拒绝。

### HMAC 规则

- 算法：HMAC-SHA256，输出 hex。
- 头：`X-Lobn-Timestamp`（Unix 秒）、`X-Lobn-Nonce`（UUID）、`X-Lobn-Signature`。
- 签名串：`{timestamp}\n{nonce}\n{METHOD}\n{path}\n{sha256(body)}`。
- 时间窗：±60 秒。nonce 在 10 分钟内不可重放。

## 4. 消息 schema

### 4.1 监控 → 总控：`smartcctv.event.v1`（归档前 · 自研 CCTV）

见 [contracts/smartcctv.event.v1.json](contracts/smartcctv.event.v1.json)。

- `type`：`face_known` | `face_unknown` | `zone_intrude` | `loiter` | `line_cross` | `crowd` | `door_request_manual`
- 本消息**不是**开门命令。总控收到后自行决策。
- **终态**：感知来自 Frigate→HA，不再强制保留本 HTTP 信封；若总控仍要统一内部事件名，在 `lobn_office` 内映射即可，不必再跑 SmartCCTV 进程。

### 4.2 总控 → ESP32：`door.command.v1`

见 [contracts/door.command.v1.json](contracts/door.command.v1.json)。

- `reason`：`face_match` | `booking_grant` | `manual`
- 只有总控发出。回执：`200 {"result":"pulsed","command_id"}`；超时总控标 `unknown`，不连发。

### 4.3 云端 ↔ 总控：授权单

见 [contracts/grant.v1.json](contracts/grant.v1.json)。回执 `result`：`opened` | `denied` | `unknown`。

### 4.4 ESP → 总控：`esp.sense.v1`

见 [contracts/esp.sense.v1.json](contracts/esp.sense.v1.json)。

- `kind`：`telemetry` | `pir` | `button`
- `edge`：`rise`/`fall`（PIR）、`press`/`release`（按钮）
- 本消息**不是**开门命令。PIR/按钮只可能触发监控 `capture/assist`。

### 4.5 总控 ↔ 云端：`alert.v1`

见 [contracts/alert.v1.json](contracts/alert.v1.json)。

- `state`：`open` | `suppressed` | `acked` | `ignored` | `recovered`
- `handled_by`：`center` | `admin`
- 总控 `POST /internal/alerts` 推送；店员确认后总控 `GET /internal/alerts/pending-acks` 回拉。

## 5. 授权状态机与扣费

```
支付/时长券核销 → frozen → pending(生成 grant)
pending → opened   ：第一次成功脉冲，扣费一次
pending → denied   ：策略拒绝或过期，解冻
pending → unknown  ：继电器超时，保持冻结，不自动重扣、不连发
unknown → pending  ：店员确认后重试
```

### 5.1 小程序按钮开门

```
学员 POST /api/door/request → 云端 DoorOpenRequest(pending)
总控轮询 GET /internal/door/requests/pending → open_by_grant → consume
```

### 5.2 人脸自动开门

监控上报 `face_known` → 总控热名单 + 有效授权 + `face_auto_open` → 脉冲。

### 5.3 门口辅助唤醒（不开门）

```
ESP pir/button → POST /api/lobn_office/esp/sense
→ 总控状态机（冷却/抑制）→ 监控 POST /api/internal/capture/assist
→ 人脸事实仍走 events；是否脉冲仍由总控策略决定
```

## 6. 人脸录入状态

云端用户：`none` → `pending` → `accepted` | `rejected`。  
`person.note` = 云端 `user_id` 字符串。

## 7. 降级表

| 依赖挂了 | 行为 |
|----------|------|
| 总控 | 所有软件开门停止；小程序显示门禁暂不可用 |
| ESP 离线 | 软件开门 `unknown`，不扣费、不连发 |
| DHT / PIR / 按钮失效 | 失去温湿度或现场唤醒；人脸循环与门命令继续 |
| 云端 | 已预取授权与已注册人脸继续；告警本地排队 |
| 云端告警接口 | 总控照常抑制与本地审计；推送重试，不影响开门 |
| 监控 | 预约与手工开门继续；人脸/辅助捕捉停止并通知店员 |
| 企业微信 | 开门不受影响；告警本地队列，>2h 普通告警丢弃 |
| 店员未确认告警 | 维持总控已做抑制；不升级成开门或锁死 |
| 第三方核销 | 自建券可用；平台券返回暂不可用 |

不可降：放行、脉冲、回执、审计。  
可暂停：通知、第三方核销、AI 管家、报表、辅助唤醒。暂停期间未开成的门不得自动补开。

## 8. 时钟

- 存储 UTC，界面 `Asia/Shanghai`。
- 总控 NTP 偏差 >2s：拒绝授权开门；已在窗口内的人脸仍受本地冷却约束。
- 授权单与总控时间差 >60s：拒绝。
- sense 单次时间戳偏差 >60s：丢弃该报文。
