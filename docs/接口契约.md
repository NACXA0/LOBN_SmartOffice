# 智慧办公室接口契约 v2（MQTT 总线）

> 字段只增不改。样例见 [contracts/](contracts/)。  
> 终态架构：[架构-HAOS四App.md](架构-HAOS四App.md)  
> 自研 CCTV 归档：[归档/决策-归档自研SmartCCTV.md](归档/决策-归档自研SmartCCTV.md)

**原则**：云端管交易、智能层管业务判定、保命层管设备脉冲、监控管感知。  
**事件 / 指令不是互相替代**：`frigate/#` 与 `business/access/grant` **都不是**继电器脉冲；脉冲只来自 `home/<node>/door/command` → ESPHome。

---

## 1. 职责矩阵

| 角色 | 可做 | 不可做 |
|------|------|--------|
| 云端 FastAPI（M 端） | 用户/预约/时长/券/排班；人脸会话**中继**（不落长期照片）；`face_status` 展示 | 发门脉冲、存 embedding、按告警自动开门扣费 |
| SmartOffice | 人员凭证/总览审计工作台；门口比对经仲裁发 `business/access/grant`；人员停用（鉴权靠 HA Ingress） | 直连摄像头独占、拉继电器、进 HA 进程、自建登录 |
| HA 本体 | 实体翻译、保命自动化（grant→command）、Ingress 权限、ZHA 等 | **零智能**（无人脸算法） |
| Frigate | 录像/检测/zone/`frigate/#`；**关 Face Recognition** | **零业务**（身份底库、谁能进门） |
| ESPHome 教室总控 | 订 command / RFID allowlist、脉冲门与警号、报 state/sense/RFID | 私有 HTTP 开门、因 PIR 自行开门、编辑白名单 |
| HA（RFID 保命） | 白名单编辑、下发 retained allowlist、未授权通知/消警 | 串口驱动；比对逻辑进 `lobn_office`；依赖云端 |
| 小程序 / FireClassroom | 下单/核销/上传/请求开门 | **不参与资产防盗**；直连 ESP；把支付成功显示成门已开 |

## 2. 关联号

`user_id` → `order_id` / `voucher_id` → `grant_id` → `command_id` → 审计。  
传感器/告警可用 `alert_id`；MQTT 消息带 `ts` + 幂等 `event_id` / `command_id`。

跨系统消息必须带齐已有关联号。

## 3. 通道（现行）

| 通道 | 用途 |
|------|------|
| MQTT `frigate/#` | 感知事实 |
| MQTT `home/#` | `home/<node>/door/*`、RFID event / allowlist、可选 sense |
| MQTT `business/#` | grant / analytics / notify |
| Add-on → Frigate/go2rtc | **仅查询**（短窗帧、events） |
| 小程序 → 云端 → Add-on | 人脸采集帧中继（店主动连出） |
| 云端 ↔ 店 | HMAC 密钥 B（或 MQTT bridge）；店主动出站优先 |
| 学员 / 店员 JWT | 云端 API；与总线密钥分离 |

**已废除（归档 SmartCCTV 后不再部署）**：密钥 A/C、`cctv.lobn:8300`、监控 HMAC `POST /api/lobn_office/events`、总控→监控 enroll/assist/passages HTTP。历史样例见 §9。

### 云端 HMAC（密钥 B，仍有效）

- 算法：HMAC-SHA256 hex。  
- 头：`X-Lobn-Timestamp`、`X-Lobn-Nonce`、`X-Lobn-Signature`；可选 `X-Lobn-Store-Id`。  
- 签名串：`{timestamp}\n{nonce}\n{METHOD}\n{path}\n{sha256(body)}`。  
- 时间窗 ±60s；nonce 10 分钟内不重放。

## 4. 总线消息（v2）

正式 JSON 文件可逐步补进 `contracts/`；下列为契约骨架。

### 4.1 `business.access.grant.v1`（Add-on → MQTT `business/access/grant`）

- 样例：[contracts/business.access.grant.v1.json](contracts/business.access.grant.v1.json)
- 字段：`schema`, `door`/`node`, `ttl_sec`, `reason`（`face_match` 等）, `subject.user_id`, `command_id`, `expires_at`, `ts`
- **不是**开门脉冲。过期或重复 `command_id` 不脉冲。仅 Add-on MQTT 账号可发此主题。

### 4.2 `home.door.command.v1`（HA / lobn_office → MQTT `home/<node>/door/command`）

- 样例：[contracts/home.door.command.v1.json](contracts/home.door.command.v1.json)
- 主题：`home/<node>/door/command`；`<node>` = ESPHome `substitutions.room_id`（如 `classroom_1`、`front_gate`）
- JSON：`schema`, `action`=`OPEN`, `ttl_sec`（1–10）, `command_id`, `ts`
- 板上亦接受纯文本 `OPEN`（缺省脉冲秒数）
- 云端 `target=gate|inner` 不变；店内 `lobn_office` 选项映射到 node
- 仅保命自动化、店员按钮或 `MqttDoorAdapter` 发布

### 4.3 `home.door.state` / sense

- 主题：`home/<node>/door/state` — 门磁 / ESPHome：`open`/`closed`；可选 `…/door/sense` pir/button 边沿。  
- **不是**开门命令。

### 4.4 `business.analytics.*`

- 例：`business/analytics/classroom_5` → `{avg, peak, ts, window_min}`  
- HA MQTT 发现为 sensor；云端可订阅落库。

### 4.5 `home.rfid.event.v1`（ESPHome → MQTT `home/<room>/rfid/event`）

- 样例：[contracts/home.rfid.event.v1.json](contracts/home.rfid.event.v1.json)
- 字段：`schema`, `event_id`, `room`, `gate`, `tag_id`, `allowed`, `transport`（`rs485`/`rs232`/`wiegand`）, `ts`
- 板上已按最后一份 allowlist 比对；`allowed=false` 时应已拉警号。HA 只做通知与审计展示。
- **不**进 `business/#`，**不**回写云端 / FireClassroom。

### 4.6 `home.rfid.allowlist.v1`（HA → MQTT `home/<room>/rfid/allowlist`，retained）

- 样例：[contracts/home.rfid.allowlist.v1.json](contracts/home.rfid.allowlist.v1.json)
- 字段：`schema`, `room`, `tags[]`, `rev`, `ts`
- HA 是唯一编辑处；ESP 缓存后离线仍按该名单比对。

### 4.7 Frigate 原生

- 以官方 `frigate/events` 为准；Add-on 适配。不用 Frigate 人脸 `sub_label` 做开门。

### 4.8 人脸状态（云端展示）

`none` | `pending` | `accepted` | `verified` | `rejected`。向量只在店内 Add-on。

### 4.8 云端 ↔ 店：授权单等

见 [contracts/grant.v1.json](contracts/grant.v1.json)、[alert.v1.json](contracts/alert.v1.json)。语义保留；店内执行改为 grant→MQTT command，不再经 SmartCCTV。

## 5. 授权与开门（逻辑）

```
支付/时长券 → frozen → pending(grant)
pending → opened ：第一次成功脉冲，扣费一次
pending → denied ：拒绝或过期
pending → unknown：执行超时，保持冻结，不连发
```

### 5.1 小程序按钮开门

云端排队 → 店侧（`lobn_office` MQTT 适配器或保命自动化）校验授权 → `home/<node>/door/command` → 回执云端。

### 5.2 识别自动开门（链路 A）

Frigate 门口 zone `person` → SmartOffice（go2rtc 短窗比对）→ `business/access/grant` → HA 保命自动化 → ESPHome。

### 5.3 辅助唤醒

ESPHome sense 上 MQTT → HA 通知；**不**直接开门。

## 6. 人脸

- 底库、比对、工作台（总览/人员/审计）在 **SmartOffice**（Frigate 关 Face Recognition）。详见 [SmartOffice.md](SmartOffice.md)。
- 主键云端 `user_id`；向量只在店内 SQLite。
- 学生：小程序会话帧经云端**中继**到 Add-on（不落长期照片）。工作人员：HA Ingress 工作台 `getUserMedia`（无 Add-on 自建登录）。
- 云端只存 `face_status` 展示；停用指令以云端为准同步到 Add-on。
- 店内 HTTP 摘要（会话、`/api/stats`、人员）见人脸专文；跨 App 事件/开门指令仍只走 MQTT。

## 7. 降级表

| 依赖挂了 | 行为 |
|----------|------|
| HA / 保命自动化 | 软件开门停；物理钥匙仍可用 |
| ESPHome 离线 | 软件开门失败/unknown；不连发 |
| Frigate | 预约/手动保命路径可开；识别自动停 |
| sidecar | 无自动 grant、无利用率；保命层照常 |
| 云端 | 已缓存排班/授权短时可用；新单受影响 |
| Mosquitto | 全店事件总线停——优先保 MQTT；可考虑本地 fallback 仅保命 |

不可降：脉冲审计、不双扣。可暂停：报表、热力、自动识别开门、取证上传。

## 8. 时钟

存储 UTC，界面 `Asia/Shanghai`。店内 NTP；授权与总线消息时间窗与旧规一致（总偏差策略在 sidecar/云端配置中钉死）。
