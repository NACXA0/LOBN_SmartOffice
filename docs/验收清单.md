# 验收场景（HAOS 四 App）

依据：[架构-HAOS四App.md](架构-HAOS四App.md)。自研 SmartCCTV **不验收**。

## 保命层

- [ ] 停掉 analytics-sidecar 后，店员/授权类保命路径仍能经 HA→`home/*/command`→ESPHome 开门
- [ ] 停掉 HA / Mosquitto 后，软件开门不可用；物理钥匙/并联按钮仍可用
- [ ] ESPHome 超时或离线 → 不连发脉冲；云端不误扣（unknown/失败语义）
- [ ] sidecar 误发 grant 时，仍可由 HA 自动化条件约束（门、时段）拦截（按配置）

## 感知与智能

- [ ] Frigate 宕机：利用率与识别自动开门停；保命开门仍可用；店员可见提示
- [ ] 摄像头对 go2rtc 连接数 ≤2（无直连旁路）
- [ ] 链路 A：known person + zone + 排班 → `business/access/grant` → 门开 → 审计有记录
- [ ] 链路 B：`business/analytics/*` 进入 HA sensor / 看板
- [ ] 链路 C：Frigate 导出 → sidecar 上传 → 云端签名链可下载

## 云端与安全

- [ ] 密钥 B 重放 / 过期 / 时钟偏差 → 拒绝
- [ ] 团购核销响应无门禁地址；开门只出现在店内审计
- [ ] `app_env=production` 且 `simulate_payment=true` → 云端拒绝启动
- [ ] 预约冲突 → 409；同一 grant 成功回执两次不双扣
- [ ] 删除/停用人员后识别自动开门失败

## 铁律抽查

- [ ] HA 自动化内无排班 SQL / 无滞留算法代码
- [ ] Frigate `config.yml` 无业务门禁规则（只有 detect/zone/record）
- [ ] 无 App 间私有 HTTP 发开门指令（仅 MQTT command + 查询型 REST）
