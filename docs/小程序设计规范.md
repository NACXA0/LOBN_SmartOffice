# 小程序设计规范

本文约定**微信小程序**的界面与交互底线：依据微信官方设计取向与苹果 [Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines)，写成可落地、可度量的通用规则，**不绑定某一业务线**。配色与量化尺寸吸收了 [移动端 UI视觉与UX交互设计规范](./系统设计/移动端%20UI视觉与UX交互设计规范.md)，并改写成微信可实现的一套方案。

亮色的感官目标是 **6 偏白 : 3 蓝 : 1 红**，暗色是 **6 偏黑 : 3 蓝 : 1 红**——这是眼睛的印象，不是按像素填色。结构记作 **6 主导（中性）: 3 辅助（层次）: 1 强调（重点）**。不照搬 iOS 系统蓝 `#007AFF`、纯黑底和大标题导航。

| 部分 | 写什么 | 谁用 |
|------|--------|------|
| **第一部分（第 1～10 节）** | 原则、尺寸、色彩、交互、转化模式 | 任意微信小程序 |
| **附录 A** | 本仓库令牌名、壳、组件类、运行配置 | 所有 `LOBN_DANA_*` 小程序 |
| **附录 B** | 场景对照、品类色、业务样板页 | **仅更新修缮**；其它业务另立附录 |

管理端 Web 另见 [管理端页面设计规范.md](./管理端页面设计规范.md)，与小程序壳不要混用布局隐喻。原则指导取舍；硬性尺寸与无障碍优先于风格偏好。工种、报价、入驻等业务名词只写在对应业务附录，不进入第一部分。

# 第一部分：通用指导

## 1. 设计原则

### 1.1 微信：F.I.T.S.

微信官方推荐可概括为 **F.I.T.S.**：

| 原则 | 含义 | 实践要点 |
|------|------|----------|
| **友好礼貌（Friendly）** | 少干扰、突出重点 | 去掉无关装饰；流程简短明确；操作进行中不插入打断性广告或弹层 |
| **清晰明确（Informative）** | 知道自己在哪、能去哪 | 页面标题、返回、加载态到位；异常提供重试与退出路径 |
| **便捷优雅（Tasteful）** | 适配手指与移动情境 | 少输入、多用选择；控件间距防误触；热区够大 |
| **统一稳定（Stable）** | 与微信及自身一致 | 视觉与交互贴近微信习惯；产品内各页风格统一，勿每页另立隐喻 |

小程序不是 App 精简版，也不是 H5 替身。核心是「**即用即走**」：打开片刻内说清能做什么、怎么做、下一步去哪。

### 1.2 苹果：HIG 八项（落到小程序）

以下将苹果移动端原则转写为微信小程序可执行表述（不依赖某一业务名词）。

#### 目标感（Clarity of purpose）

先定「这一屏用户要完成什么」，再排版。一屏一事；首屏不堆统计条、促销贴片、多段营销。

#### 能动性（Agency）

界面帮用户做事，不替用户做完、不藏状态。随时可见阶段、金额、登录态、错误原因；主按钮禁用时说明原因；脏表单离开可确认。

#### 责任感（Accountability）

以用户利益与合规为先。隐私与授权边界写清楚；金额分项展示；支付前协议勾选；危险操作二次确认；空态写「暂无」，不伪造业务数据。

#### 熟悉感（Familiarity）

沿用用户已会的模式：左返回、右上角系统胶囊、底 Tab、列表左文右 chevron、微信支付 / 手机号授权 / 订阅消息等微信惯用流程。勿另造难懂手势体系。

#### 灵活（Flexibility）

适配安全区、刘海、键盘顶起；竖屏为主；游客与登录用户尽量走同一流程的不同阶段，而不是两套完全不同的壳。

#### 简洁（Simplicity）

每个控件一个职责；返回用符号而非冗长文案；长说明可折叠；不为「好看」多层套卡。

#### 匠心（Craft）

按下态、圆角、字号、间距用统一体系；动画短促；图标风格一致。

#### 愉悦感（Delight）

成功用轻反馈；等待用诚实文案；情绪与场景匹配，克制礼花、大发光、贴片徽章。

### 1.3 从用户视角出发的五个实战原则

1. **信息层级一眼看懂**  
   明确本页唯一核心目标，用字号、对比、留白突出主标题 / 主按钮 / 关键数据；次要信息降权或折叠。用户没有耐心「慢慢探索」。

2. **交互直觉优先，克制炫技**  
   优先下拉刷新、左滑删除、底 Tab 等微信肌肉记忆。自定义交互必须有明确按下 / 加载 / 结果反馈。输入能省则省：少必填、自动填充、正确 `input` 类型。

3. **转化路径做减法**  
   从入口到目标，理想控制在约三步内。每多一页、多一次跳转都是流失点。善用一键手机号、微信支付等原生能力缩短路径，而不是生硬打断。

4. **在约束下做减法**  
   屏小、时短、耐心有限；像素与交互都服务于用户目标。好的体验往往是「用完几乎注意不到设计」。

5. **异常可恢复**  
   加载失败、空数据、无权限都要有下一步：重试、返回、去登录——而不是死胡同。

### 1.4 交互共识（可执行）

这些条优先于「再写一句说明」。

| 共识 | 做法 | 量化 |
|------|------|------|
| **交互优于说明文本** | 控件已经表达的动作，不在旁边再写一句。说明只补「缺什么、点哪里」 | 同一屏同一动作的解释 ≤ 1 句；空态、错误、禁用原因才允许这句话 |
| **象形优于说明文本** | 类别、状态、导航用一个公认图标，不写「请点击下方按钮进行操作」 | 返回、关闭、搜索、收藏可以只有图标，热区仍 ≥ 88rpx。主按钮、支付、删除必须有动词，禁止纯图标 |
| **识别优于回忆** | 把选项摆出来选，不要求记住上一页的数字或名词 | 能用选择器、chip、列表就不做开放填空 |
| **一个主操作** | 一屏只有一个实心主按钮 | 放在拇指区（屏下约 1/3）或内容末尾。两个同权重实心蓝 = 不合规 |
| **选择宜少** | 同级选项一多，人就选不动 | 同屏并列选项 ≤ **6**。超过就搜索、分组或分步。词库走第 5.4 节抽屉，不铺满屏按钮 |
| **按下立刻有反馈** | 手指落下就要看见变化，不等接口 | ≤ **100ms**（本规范按下动画 **80ms**） |
| **可逆直接做，不可逆才确认** | 收藏、筛选、切换立即生效，并给撤销或再点一次取消 | 删除、支付、放弃已填内容才弹确认。确认按钮写后果（「删除地址」），不写「确定」 |
| **邻近成组** | 相关的靠近，无关的拉开 | 组内 **8pt**，组间 **24pt**。见第 2.6.1 节 |
| **错误贴着字段** | 校验写在该输入正下方 | 不只用页顶 Toast 报告第几个字段错了 |
| **占位符不是标签** | 输入框有可见标题，placeholder 只给例子 | 禁止用 placeholder 代替字段名 |
| **先内容后装饰** | 能删的说明、徽章、渐变先删 | 玻璃只用于第 4.5 节列出的浮层。列表卡片、订单空态用纸色 |

数量、时间和热区的依据见第 1.5 节。格式塔、习惯、启发式、峰终、孤立效应、美观可用性见第 1.6 节：设计时要用，不能用公式验收。

### 1.5 可用数值约束的法则

公式里的 a、b 是拟合常数，设计稿不计算它们。公式只用来决定收哪一头：距离、宽度、选项数、响应时间。

#### 菲茨定律

指向目标的时间：

`T = a + b · log₂(D / W + 1)`

T 随距离 D 变大，随目标宽度 W 变大而变小。

| 落地 | 数值 |
|------|------|
| 屏底主操作 | 宽度取内容区全宽，且 ≥ **375rpx**（750 稿屏宽的一半）；高度 ≥ **88rpx**。行内文字按钮、次按钮不必拉到半屏 |
| 底栏 | 放在屏下沿，让 D 落在拇指自然弧线里。主路径不要放到屏顶另一角 |
| 相邻可点 | 间距 ≥ **16rpx**（`--sp-2`，8pt），避免 W 够大仍误触邻项 |
| 返回 | 留在左上，与胶囊对齐。返回的 D 大是平台习惯，不用菲茨把它搬到底栏 |

核对：同一任务的完成时间、误触、点击落点。改按钮尺寸前后对比即可，不必拟合 a、b。

#### 希克定律

等可能选项时，决策时间：

`RT = a + b · log₂(n)`

n 是当前这一步要选的个数。n 从 4 增到 8，决策时间大约多一个常数 b，不是慢一倍；但再往上堆，放弃会先出现。

| 落地 | 数值 |
|------|------|
| 同屏并列入口 | **4～6** 个。首页宫格同样。多的收进「更多」，不要第 7 个实心入口 |
| 价格、套餐 | **≤ 3** 档 |
| 分步表单 | 每一步只做一组决定（先地区，再街道，再门牌） |
| 与「少点击」冲突时 | 希克优先：不为了少一次点击，把一屏选项堆过 6 个 |

核对：从打开选项到点中的时间、中途放弃。界面上不要写 log。

#### 米勒定律

短时记忆大约 **7±2** 个组块，超出就开始错。这是实验室上限。手机上收得更紧，不把 9 个字段当成还合格。

| 落地 | 数值 |
|------|------|
| 底栏 Tab | **2～5**（建议 3～4）。超过 5 个是微信硬限制，不会按设计渲染 |
| 一段表单 | 字段 ≤ **5**。再多就分下一段，段与段用标题隔开 |
| 长列表 | 连续条目超过 **7** 条且没有分组标题，必须加标题把块切开 |
| 导航层级名称 | 分组标题用用户的词（「手机」而不是内部编码） |

核对：填错、漏填、找不到分组。不要让用户背出有几项来证明合规。

#### 多赫蒂阈值

交互节奏低于约 **400ms** 时，人还觉得系统跟着自己。超过这个间隔又没有任何变化，会以为没点上。

按下态 ≤ **100ms** 已经满足「收到了」。400ms 约束的是这份确认，不是接口结果本身。

| 时刻 | 界面必须怎样 |
|------|----------------|
| ≤ 100ms | 按下态出现 |
| ≤ 400ms | 若结果还没回来，进入按钮内加载或该区域的转圈。400ms 内能结束的，不要转圈 |
| ≤ 2s | 结果尽量回到界面（2 秒是预算，不是公式） |
| 明知要超过 1s 的首屏 | 骨架在 **200ms** 内出现，禁止白屏干等 |

体验预算（用开发者工具 Audits 和线上性能监控看，不是菲茨那种公式）：

| 项 | 预算 | 性质 |
|----|------|------|
| 冷启动 | ≤ 3s | 体验预算 |
| 热启动 | ≤ 1s | 体验预算 |
| 首屏内容 | ≤ 1s；有缓存先画缓存 | 体验预算 |
| 滚动与转场 | 目标保持跟手（约 ≥ 50 FPS） | 体验预算，掉帧要查，不把每一帧写成合同 |
| 核心接口 | TP90 ≤ 500ms | 服务端预算。界面仍按慢于 500ms 准备加载态 |
| 主包体积 | ≤ 2MB | 微信硬限制 |

#### 三次点击（预算，不是定律）

核心任务从入口到完成 ≤ **3** 次点击（查订单、领券、发起预约这一类）。第 4 次还没到，就减层级，而不是加说明。

这不是公式。点击少但每步都不确定，比多一步更差。和希克冲突时按上一节：每步 n ≤ 6，不为了凑进 3 次把选项堆满。核对方式是把任务交给人走一遍，数点击并看是否走错，不是在稿子上打勾。

### 1.6 只能间接验证的法则

下面几条用来决定取舍。它们没有可代入界面的公式。改完是否真的更好，只能靠可用性测试或用户调研（任务是否完成、是否走错、事后记得什么）。启发式走查可以发现问题，不能代替这些测试。

| 法则 | 设计时 | 不要当成 |
|------|--------|----------|
| **格式塔** | 接近：组内 8pt、组间 24pt。相似：同一类用同一种 chip。连续：步骤和列表沿一个方向排。共同区域：一张卡片就是一块。图底：纸色内容浮在画布上 | 「看起来是一组」已被证明。要看人是否点进错误的一组 |
| **雅各布** | 人大部分时间在别的产品里。沿用微信习惯：左返回、右上胶囊、底 Tab、下拉刷新、左滑删除、微信支付 | 新隐喻更先进。要比的是任务时间和误操作，不是新旧风格投票 |
| **尼尔森十条** | 状态可见 → 按钮五态与第 6.1 节。用户控制 → 返回、取消、撤销。一致 → 令牌。防错 → 禁用写原因、不可逆才确认。识别而非回忆 → 第 1.4 节。防错后的恢复 → 第 6 节。帮助从简 → 交互优于说明 | 十条都写进页面。灵活高效不靠隐藏手势当唯一路径 |
| **峰终** | 人记住高峰和结尾。把最慢的等待做成诚实的加载，把成功结尾做短，把失败结尾做成还能重试 | 结尾好看就等于流程可用。高峰和结尾的印象要问用户，不能自检 |
| **冯·雷斯托夫** | 与众不同的那一个会被注意到。一屏只留一个强调（价格或危险，第 4 节） | 强调越多越好记。多了效应就没了 |
| **美观可用性** | 间距、圆角、对齐让界面不像坏掉的。它解释为什么要守令牌 | 好看就可用。美观评分和任务成功率分开测 |

## 2. 尺寸、导航与组件（硬性标准）

以设计稿宽度 **750rpx** 为基准等比缩放。

### 2.1 导航栏与胶囊

- 顶栏通常含返回与页面标题；用户须始终知道当前页是什么。
- **必须为微信右上角胶囊预留空间**，内容与热区不得与胶囊重叠。
- 自定义导航时，返回控件宜与胶囊**同高、同顶**，左右边距镜像，避免贴死屏幕左上角难点。

### 2.2 底部标签栏

- Tab 数量 **2～5**，建议 **3～4**。这是微信硬限制，也是米勒定律在手机上的收紧（第 1.5 节）。
- 图标建议约 **81×81 px**（实现可按视觉缩放）；选中 / 未选中须有明确颜色或形态区分。
- 有底栏时，页面内容区须预留下方避让，避免列表被挡住；主操作底栏（提交 / 支付）再抬高，避开 Tab 与 Home Indicator。

### 2.3 触控与按钮

- 可点热区不小于 **44pt**（**88rpx**）。相邻可点间距 ≥ **16rpx**。依据是菲茨定律，见第 1.5 节。
- 屏底主操作宽度 ≥ **375rpx** 且为内容区全宽；行内次按钮不拉到半屏。一屏主行动只有一个。

### 2.4 字体与字号

- **默认可读正文 34rpx**（约 17pt，对齐 HIG Body）；**用户能读到的字不得小于 28rpx**（微信建议底线，辅助文 / 底栏标签）。
- 行高约为字号的 **1.4～1.6**。字重只使用 **400 / 600 / 700**：正文 400，卡片名与按钮 600，空态标题与价格可 700。禁止 500 与 800 混用。
- 使用**平台默认字体**（iOS 多为苹方，Android 多为系统黑体 / 思源系）；**不建议强制指定自定义字体**。
- 更小字号（如 24rpx）仅可用于角标、步骤点等**非阅读**标签，禁止作正文或列表主文。
- 小程序无 iOS 大标题折叠导航；大标题保持克制（约 40rpx），勿照搬 HIG Large Title 34pt。

### 2.5 布局基准

- 内容相对安全区排布：`env(safe-area-inset-*)`。
- 列表、表单、详情分区清晰；卡片用于承载一组相关字段，不为装饰多层嵌套。
- 屏幕左右边距、组件间距见 **2.6 设计令牌**。


### 2.6 设计令牌（视觉原子层）

本节定义可复用的视觉原子变量。间距、圆角、表面层级须引用令牌；
页内禁写非刻度魔法数（如 `margin: 15rpx`）。基准：750rpx = 375pt（2rpx ≈ 1pt），
令牌值以 pt 为设计原点、rpx 为实现单位。

**允许的例外**（不属于间距令牌）：1px 发丝线、图标固有尺寸、`env(safe-area-inset-*)`、胶囊对齐几何（见 `nav_layout.js`）。

#### 2.6.1 间距刻度（4pt 基数）

先按关系选档，再写变量。下表的 pt 是设计尺寸，rpx 是代码尺寸（2rpx ≈ 1pt）。说「16」时指 **16pt = 32rpx**，不是 `16rpx`。

| 关系 | pt | rpx | 变量 | 只能用在 |
|------|----|-----|------|----------|
| 图标与相邻文字 | 4 | 8 | `--sp-1` | 图标和标签、价格和单位 |
| 同一组里的小元素 | 8 | 16 | `--sp-2` | 一行里的 chip、列表行内的主副文、按钮之间 |
| 卡片内边距 | 16 | 32 | `--sp-4`（`--card-pad`） | 卡片、抽屉内容、主按钮水平留白 |
| 卡片与卡片 | 24 | 48 | `--sp-5` | 卡片间距、互不相关的模块间距 |

更大的留白仍用刻度，不另造数值：

| 变量 | rpx | ≈pt | 用途 |
|------|-----|-----|------|
| `--sp-3` | 24 | 12 | 仅作旧页边距 `--page-gutter`。新页左右边距用 `--sp-4`（16pt），与卡片内边距对齐 |
| `--sp-6` | 64 | 32 | 大分区、页尾在安全区之外的额外避让 |
| `--sp-7` | 96 | 48 | 空态图标到文案 |

禁止 `6 / 10 / 12 / 14 / 18 / 20 / 22 / 28rpx` 这类中间值。组内不要用到 24pt，那会把一组拆成两块；卡片之间不要用 8pt，那会粘成一块。

#### 2.6.2 圆角刻度与同心规则

| 用途 | pt | rpx | 变量 |
|------|----|-----|------|
| 小元素（标签、角标、小图） | 4～8 | 8～16 | 更小用 `--r-sm`（4pt），输入框与方按钮用 `--r-md`（8pt） |
| 卡片 | 12 | 24 | `--r-lg` |
| 弹窗、底部抽屉顶部 | 16 | 32 | `--r-xl` |
| 胶囊按钮、chip、底栏 | 高度的一半 | — | `--r-pill`（写法 `999rpx`）。高 88rpx 的胶囊，视觉圆角就是 44rpx |

**嵌套**：`外圆角 = 内圆角 + 这一圈的间距`。  
例：卡片外圆角 12pt（24rpx），内边距 8pt（16rpx，`--sp-2`），卡内图片圆角 = 12 − 8 = **4pt**（`--r-sm`）。  
若间距 ≥ 外圆角（卡片内边距已是 16pt，大于圆角 12pt），内角落在直线边上，公式不适用：内圆角取 `--r-sm` 或直角，并目视确认。不要为了套公式把卡片内边距从 16pt 改小。

#### 2.6.3 暗色表面分层

亮色用阴影表达层级；暗色内容卡片不用黑色投影，改用表面亮度阶梯（海拔越高、表面越亮）。
玻璃浮层（底栏 / 返回 / 遮罩）仍用 `--glass-*` 模糊与阴影，禁止改回实色块。

| 变量 | 层级 | 说明 |
|------|------|------|
| `--c-bg` | base | 页面底，冷偏近黑（约 `#12161c`） |
| `--c-surface` | elevated 1 | 卡片、分组（约 `#1c2430`） |
| `--c-surface-high` | elevated 2 | 浮起模块、卡内卡（约 `#263040`） |
| `--glass-*` | overlay | 弹层 / 遮罩 |

禁止把三层表面压成同一色。

#### 2.6.4 层级刻度（z-index 令牌）

页面固定层用**互不重复的小整数**表达高下，不用 `100 / 1000 / 19999` 这类大数堆叠。大数只能说明「谁盖谁」，看不出一屏实际叠了几层；两个浮层共用一个数时无法裁决，`page-container` 的 `19999` 更会挡住一切后续浮层。

| 层 | 令牌 | 用途 |
|----|------|------|
| 1 | `--z-content` | 页内内容 |
| 2 | `--z-cat` | 首页头图下沿分类条（必须低于顶栏） |
| 3 | `--z-nav` | 壳顶栏；页内筛选抽屉 |
| 4 | `--z-back` | 圆形返回与浮层标题（高于抽屉，返回始终可点） |
| 5 | `--z-footer` | 页内底操作条（详情、购物车 footer） |
| 6 | `--z-cart` | 商城悬浮购物条（低于底栏） |
| 7 | `--z-dock` | 底部 Tab / 工作台 dock |
| 8 | `--z-sheet` | 页内抽屉 / sheet（打开时盖住 5，不盖 9） |
| 9 | `--z-mask` | 全屏遮罩、lightbox、`page-container` 遮罩 |

规则：

- **两层不得共用同一个数**：分类条若用 2，顶栏就不能也是 2。
- 调整相对顺序时**成对改**，禁止只改底栏一个数。
- `page-container` / `root-portal` 的 `z-index` 与遮罩同走 `--z-mask`，不再写大数。
- 每个收起 / 展开位置按**两态**各量一次：抽屉打开时可见玻璃 ≤ 2 层（第 4.5 节）；关闭后下层恢复可点。

### 2.7 组件尺寸（量化）

基准仍是 750rpx 宽。下表是硬性尺寸；颜色见第 4 节。热区可以大于视觉尺寸，不可小于。

| 组件 | 尺寸 | 圆角 | 文字 |

### 2.8 按钮的五个状态

每个按钮都要有这五态。小程序没有悬停，不要做第六套「悬停色」。按下不换色相。

| 状态 | 含义 | 主按钮 | 次按钮 | 危险按钮 | 行为 |
|------|------|--------|--------|----------|------|
| **默认** | 现在可以做 | 行动蓝底，白字，字重 600 | 纸色底，行动蓝字，1rpx 分割线 | 美术红软底，危险红字 | 可点 |
| **按下** | 手指还在按钮上 | 80ms 内透明度 **0.68**，缩放 **0.96**，颜色不变 | 同左 | 同左 | 手指滑出按钮则取消，不触发 |
| **加载** | 已经提交，在等结果 | 宽高不变；字改为「提交中」或保留动词，左侧 32rpx 转圈；透明度保持 1 | 同左，转圈用行动蓝 | 同左，转圈用危险红 | **不可再点**。转圈从按下满 **400ms** 才出现（见第 6.1 节）；原生 `button` 的 `loading` 属性第 0ms 就出圈，实现须延迟置 true。预计 1～3s。超过 3s 仍留在按钮内，不换成全页骨架 |
| **禁用** | 现在不能做 | 整体透明度 **0.4**，不另画灰蓝 | 同左 | 同左 | 不接收点击。按钮外 **8pt** 内有一句原因（「请先填写地址」） |
| **结果** | 这件事有结论了 | 成功：按钮恢复默认可再点，或页面离开；用 Toast，不把按钮永久改成「已完成」 | 同左 | 失败：回到默认，错误写在按钮外，用危险红字 | 成功且流程结束就离开本页。失败留在本页，可立刻重试 |

主 / 次 / 危险不要同时做成实心高饱和。危险的实心填色只出现在确认弹层里的那一个确认按钮。

## 3. 无障碍设计

无障碍已从倡议走向标准。国家标准 **GB/T 45395-2025《信息技术 小程序应用无障碍技术要求》** 从组件、交互、设计提出要求。实践底线：

- 文本与背景对比度至少约 **4.5:1**。
- **关键信息不能仅靠颜色区分**（须搭配文字或图标形态）。
- 这不仅合规，也惠及强光、单手、情境性障碍下的普通用户。

小程序无悬停：关键操作必须可触达，不依赖悬停态。图片承载关键信息时，价、名、状态等仍须有文本备份。

## 4. 色彩系统（6 主导 : 3 辅助 : 1 强调）

全产品只此一套色。亮色看过去是 **6 偏白 : 3 蓝 : 1 红**，暗色看过去是 **6 偏黑 : 3 蓝 : 1 红**。这是眼睛的印象，不是「蓝必须占 30% 像素」。差异靠**明度、饱和度、冷暖**拉开，不靠把某一色铺满。

| 份额 | 角色 | 靠什么拉开 | 亮色印象 | 暗色印象 |
|------|------|------------|----------|----------|
| **6 主导** | 中性 | 高明度或低明度，饱和度接近 0 | 偏白的画布、纸、软底、硬底、正文墨色 | 偏黑的同一套表面 |
| **3 辅助** | 层次 | 同一冷色相，饱和度分档 | 很浅的美术蓝做层次，一小块行动蓝表示「能点」 | 比画布略抬亮的蓝灰，行动蓝更亮以便白字 |
| **1 强调** | 重点 | 暖色、比辅助更少、一屏只强调一件事 | 珊瑚价签，或更深的危险红 | 珊瑚更亮，危险红仍深于美术红 |

页内禁止裸写主色 hex；角色只许用第 4.2 节的变量。品牌氛围只出现在壳层。内容区用纸色和正文色。

这套蓝不是 iOS 系统色。不要用 `#007AFF`、`#F2F2F7`、`#FF3B30` 替换令牌：系统蓝饱和度过高，会把洗染和可点的蓝收成一种；系统灰底会拿掉冷蓝层次；系统红会让价格和删除变成同一种红。底栏选中用 `--c-blue-deep` 和 `--glass-pill`，不用青绿。

### 4.1 怎么拉开，而不是怎么填满

- **主导**用中性。画面大部分应能被说成「偏白」或「偏黑」。不要为了好看把卡片改成蓝底。
- **辅助**用蓝色的深浅，不增加第二种冷色。洗染、软底、选中胶囊是低饱和；行动蓝是这一家里唯一的中高饱和，只给可点的东西。不要把按钮放大来「凑出蓝色」。
- **强调**一屏只做一件事：要么价格（美术红），要么破坏（危险红）。两件都要出现时，价格保持珊瑚，删除更深，不要两个一样红。危险红实心最多 **1 个**（确认弹层里的确认按钮）。美术红不作按钮底。
- 成功、警告是语义色，不参与这 6:3:1。它们用绿和橙，因为蓝和红已经被「能点」和「重点」占用。必须配文字或图标。饱和度同样 ≤ **70%**。
- 彩色（蓝、红、成功、警告）的 HSL 饱和度 ≤ **70%**。美术洗染必须能被说成「带一点色的白」或「带一点色的黑」。

同一色相必须拆成美术与行动（或危险），不能共用一个饱和度：

| | 明度 | 饱和度 | 偏色 | 渐变 | 出现位置 |
|---|------|--------|------|------|----------|
| **美术蓝** | 亮色接近白；暗色只比画布抬一档 | 远低于行动蓝 | 冷 | 只在壳顶，同色相、低对比 | 洗染、蓝软底、选中胶囊 |
| **行动蓝** | 中高；白字对比 ≥ 4.5:1 | ≤ 70%，负责「可点」 | 冷，与美术蓝同色相 | 主按钮最多一段同色微渐变 | 主按钮、链接、焦点环 |
| **美术红** | 低于按钮，不要荧光 | 低于行动蓝 | 暖珊瑚，忌洋红 | 仅非点击装饰上的同色极弱渐变 | 价格、小标记 |
| **危险红** | 比美术红更深 | 中等，≤ 70% | 偏暗，与美术红不是同一色 | 不用 | 失败、删除、不可逆 |

禁止：微信绿（`#07c160` 一类）抢主按钮、内容卡片彩虹渐变、高饱和铺底、贴片徽章堆叠、把美术红或危险红当品牌色。

### 4.2 色相职责

一个变量只做一件事。按下不换色：可点元素用透明度 **0.68** 加缩放 **0.96**（见第 7 节）。禁用用整体透明度 **0.4**，且不接收点击；不要再画一套灰蓝按钮。

#### 主导：中性底

从下到上只抬亮度，不换色相。亮色越往上越白，暗色越往上越亮，禁止三层压成同一色。

| 职责 | 变量 | 亮色 | 暗色 | 用法 | 禁止 |
|------|------|------|------|------|------|
| 画布 | `--c-bg` | `#f2f7fc` | `#12161c` | 页面最底。偏冷，不是纯白 / 纯黑 | 上面再铺一张同色全屏卡 |
| 纸 | `--c-surface` | `#ffffff` | `#1c2430` | 卡片、分组、输入聚焦后的底 | 暗色上再加黑投影。亮色阴影只用 `0 10rpx 28rpx rgba(28,36,52,0.04)` |
| 软底 | `--c-surface-high` | `#eef3f9` | `#263040` | 卡内卡、未聚焦输入、分段槽 | 当成可点的选中态 |
| 硬底 | `--c-chip-muted` | `#e8eaed` | `#3a4454` | A 类词库未选格；中性，不带蓝 | 用美术蓝软底代替未选格 |
| 分割 | `--c-line` | `#e9edf4` | `#2c3544` | 1rpx 列表分隔、默认边 | 用正文色或行动蓝当分割 |

抽屉（控制面板、状态抽屉，小程序里没有常驻侧栏）的内容底用纸色或第 4.5 节玻璃，不另设侧栏色。

#### 辅助：蓝（用来分层，不是用来铺面）

壳顶渐变只许这一条：顶色停住约 18% 高度，中色约 52%，底色回到画布。停在顶栏，不染进卡片。洗染底的颜色等于画布，看起来回到主导色。

| 职责 | 变量 | 亮色 | 暗色 | 用法 | 禁止 |
|------|------|------|------|------|------|
| 洗染顶 | `--c-wash-top` | `#c9daf0` | `#1c2a3d` | 壳顶栏实底、壳渐变起点 | 铺进内容卡片；做成海军蓝块 |
| 洗染中 | `--c-wash-mid` | `#e0edf7` | `#162233` | 壳渐变中段 | 单独当按钮或标签底 |
| 洗染底 | `--c-wash-bottom` | `#f2f7fc` | `#12161c` | 壳渐变结束，必须等于画布，观感回到主导色 | 与 `--c-bg` 不同色 |
| 美术蓝软底 | `--c-blue-soft` | `#eef3fc` | `#1e2c48` | 选中标签底、空态标、弱提示底 | 当按钮底 |
| 选中胶囊 | `--glass-pill` | `#d6e4ff` | `#2a3f66` | 底栏滑动选中块，不透明 | 改成青绿或成功绿 |
| 行动蓝 / 品牌 | `--c-blue` | `#3b6fd9` | `#5b87e0` | 主按钮底、链接、焦点环。白字 | 大面积页面背景 |
| 行动蓝深 | `--c-blue-deep` | `#2456b8` | `#8eb0f0` | 亮色：次按钮字、需要更深的蓝字。暗色：链接与选中字（比按钮更亮） | 暗色里把它当按下色。按下一律走透明度 |

品牌色就是行动蓝。不另设 logo 色、紫色或第二主色。若产品有多端（C 端 / 履约端 / 经营端），可用**同色相、不同明度**的端洗色，仅出现在该端顶栏与该端主按钮，正文与列表仍用 `--c-ink` / `--c-surface`；具体变量名见附录 A。品类区分色只给分类图标与只读 chip，不进按钮底；业务品类映射见附录 B。

焦点环：2rpx 实线 `--c-blue`，不加外发光。

#### 强调：红（一屏一个重点）

| 职责 | 变量 | 亮色 | 暗色 | 用法 | 禁止 |
|------|------|------|------|------|------|
| 美术红 | `--c-red` | `#d98472` | `#e8a090` | 价格、非点击暖标记 | 按钮底、错误文案 |
| 美术红雾 | `--c-red-mist` | `rgba(217,132,114,0.12)` | `rgba(232,160,144,0.16)` | 一小团装饰。有价格或危险按钮时就不要再加 | 承载文字、铺成背景 |
| 美术红软底 | `--c-red-soft` | `#fff3f0` | `#3a2824` | 危险按钮的浅底（字仍用危险红） | 当成功或警告底 |
| 危险红 | `--c-danger` | `#c94a4a` | `#d96a6a` | 删除、失败、不可逆确认 | 价格、装饰、主按钮 |

危险操作的按钮优先「危险红软底 + 危险红字」。实心危险红只给二次确认里的那一个确认按钮。

#### 文字

文字用实色分档，禁止靠白色透明度分出主次。

| 职责 | 变量 | 亮色 | 暗色 | 对比度 | 用法 |
|------|------|------|------|--------|------|
| 正文 | `--c-ink` | `#1c2434` | `#e8eef6` | 在画布和纸上 ≥ 4.5:1，目标 ≥ 7:1 | 标题、正文、列表主文 |
| 次强辅助 | `--c-muted-strong` | `#4a5263` | `#c5cedb` | ≥ 4.5:1 | 需要比辅助更清楚的次文 |
| 辅助 | `--c-muted` | `#5a6578` | `#a8b3c4` | ≥ 4.5:1 | 说明、未选中、时间以外的次要信息 |
| 占位 | `--c-hint` | `#8b95a7` | `#6b7588` | 允许低于 4.5:1 | 占位符、禁用说明。不承载金额、状态、错误 |
| 反白 | `#ffffff` | `#ffffff` | `#ffffff` | 在行动蓝上 ≥ 4.5:1 | 主按钮字、深色洗色顶栏上的标题 |

链接在亮色用 `--c-blue`，在暗色用 `--c-blue-deep`，都要在纸色上 ≥ 4.5:1。改任何一档字色后，用画布和纸色各测一次。

#### 语义色（不占主导 / 辅助 / 强调）

| 职责 | 变量 | 亮色 | 暗色 | 用法 |
|------|------|------|------|------|
| 成功 | `--c-ok` | `#0f7a4a` | `#3dba7a` | 完成、通过。配文字或对勾 |
| 成功软底 | `--c-ok-soft` | `#e8f8ef` | `#163028` | 成功提示底 |
| 警告 | `--c-warn` | `#b45309` | `#e0a060` | 待处理、额度、需注意的分类图标 |
| 警告软底 | `--c-warn-soft` | `#fff7ed` | `#3a2a18` | 警告条底 |
| 警告字 | `--c-warn-ink` | `#9a3412` | `#f0c089` | 警告条上的字，保证在软底上 ≥ 4.5:1 |

成功不是微信绿。收藏等「标一下」可用警告色，不代表出错。

### 4.3 暗色

暗色不是把亮色整体压暗。主导换成偏黑冷灰，辅助蓝和强调红在暗底上用明度重新拉开：

- 画布 `#12161c`，不用 `#000000`。
- 纸和软底只加亮度（`#1c2430` → `#263040`），不加投影。
- 行动蓝按钮 `#5b87e0` 仍铺白字。链接改用更亮的 `#8eb0f0`（变量名仍是 `--c-blue-deep`，暗色下它比按钮更亮）。
- 美术红 `#e8a090` 比亮色更亮、更干净，不要收成暗红。
- 危险红 `#d96a6a` 比美术红更深，在暗底上仍可读。

玻璃保留：深色半透明 + 上沿细高光 + 原模糊半径。禁止改回实色块。壳顶栏仍是洗色实底。

外观在设置里三选（跟随系统 / 亮色 / 暗色），全小程序共用。跟随系统走 `prefers-color-scheme`；强制暗色加 `.theme-dark`，强制亮色加 `.theme-light`。

### 4.4 令牌索引

上表即标准色板。实现时集中在页面根选择器与暗色覆盖类（本仓库见附录 A 的 `app.wxss`）。业务页只写 `var(--c-*)`。端洗色与品类 chip 是仅有的例外，仍须引用已登记变量，禁止页内新 hex。

### 4.5 玻璃与顶栏材质

顶栏和玻璃是两件事。壳顶栏用实色洗染，不做成 iOS 那种整条毛玻璃导航。玻璃只表示「浮在内容之上」。

| 材质 | 用在 | 不用在 |
|------|------|--------|
| 实色洗染 `--c-wash-top` | Tab 壳、工作台壳等可下滑主壳的顶栏 | 整条模糊导航；透明到能看见滚上去的列表 |
| 玻璃 | 底栏胶囊、圆形返回、控制/状态抽屉、盖在头图下沿的分类条 | 列表卡片、空态卡、输入框、普通内容卡 |
| 无顶栏 | 营销首页：头图贴顶。左上可有对齐系统胶囊的浮钮，浮钮不是玻璃导航条 | 再叠一条实色或模糊顶栏把头图截断 |

层级从下到上：画布 → 洗色壳或头图 → 纸卡片 → 玻璃浮层。同时能看见的玻璃最多两层：底栏一层，再加上圆形返回、抽屉或首页分类条里的一层。不要第三块。

| 元件 | 模糊 | 蒙版变量 | 描边 | 备注 |
|------|------|----------|------|------|
| 底栏胶囊 | `blur(26px) saturate(1.45)` | `--dock-capsule-bg` 亮 `rgba(255,255,255,0.38)` / 暗 `rgba(28,36,48,0.42)` | 2rpx `--dock-capsule-border` | 上沿内高光 `inset 0 1rpx 0 rgba(255,255,255,0.9)`（暗色高光降到约 0.15）。选中块用 `--glass-pill`，不是青绿 |
| 圆形返回 | `blur(16px)` | `--glass-back` 亮白 92% / 暗 `rgba(28,36,48,0.82)` | 1rpx `--glass-back-border` | 阴影用 `--glass-back-shadow` |
| 头图下沿分类条 | `blur(16px)` | 亮白约 38%，与底栏胶囊同级 | 1rpx 白 | 只许这一条盖住头图底边。圆角可以大于卡片（约 48rpx），其他卡片仍用 12pt |
| 控制 / 状态抽屉 | `blur(28px) saturate(1.55)` | 亮白约 92%；暗用 `--glass-bg` | 1.5rpx 白或 `--glass-border` | 顶圆角 `--r-xl`，下滑或点遮罩关闭 |
| 遮罩 | 可不模糊 | 亮 `rgba(28,36,52,0.45)`；暗可提到约 0.55 | — | 盖住页面，不盖住系统胶囊的可点区 |

亮色玻璃阴影带一点蓝（`rgba(36,72,130,0.14)`～`0.16`），不要绿色阴影。去掉模糊只留半透明，不算玻璃。文字不直接放在大面积毛玻璃上；抽屉里的字放在纸色或软底块上。滚动不要求顶栏从透明变模糊：壳顶栏保持洗色实底，避免内容穿进状态栏。

## 5. 交互、表单与转化

### 5.1 交互

- 基础交互优先微信默认规范；自定义须有视觉反馈。
- Tab 切换勿用会强制「自右向左」的路由方式盖过预期方向（实现细节见附录）。
- 下拉刷新、加载中、成功 / 失败提示文案短且可行动。

### 5.2 表单

- 减少必填；能选则选（picker、选择页）。
- 调用合适键盘类型；超限时主按钮不可用并说明原因。
- 防抖避免重复提交；最终以服务端校验为准。

### 5.3 转化路径

- 核心闭环尽量短；能用原生能力缩短步骤则用之。
- 支付、授权、订阅等触点自然嵌入，避免生硬打断浏览。

### 5.4 标签与 Chip（按职责选用）

「标签」不是单一控件。先判定职责，再选形态；**禁止**把词库多选、互斥枚举、只读元数据画成同一套交互。

| 职责 | 适用场景 | 形态 | 选中态 | 禁止 |
|------|----------|------|--------|------|
| **A. 词库多选** | 可检索标签词库（选项多、需搜索） | 表单「已选区 + `+`」→ 底部 `page-container` 抽屉；抽屉内已选区 + 搜索 + **两列灰格** | 已选：品牌软底 + 品牌字；未选格：中性灰底 | 逗号文本框手填；删标签无确认；抽屉高度长期压在 ≤1/2 屏 |
| **B. 互斥枚举** | 个人/企业、优先级、状态筛选、评价类型 | 行内胶囊 chip，单选 | 实心行动蓝 + 白字（或软蓝底 + 深蓝字，二选一页内统一） | 上 A 类抽屉；两列灰格 |
| **C. 可选多选（短列表）** | 评价服务标签等 ≤12 个固定项 | 行内胶囊，多选点按切换 | 软蓝底 + 深蓝字（与「已选」一致）；不用成功绿冒充选中 | 无故改成 A 类抽屉；用危险色表示选中 |
| **D. 分段选择** | 2～4 项均分的互斥分段（如对象类型） | 等宽圆角块（非胶囊）横排 | 软蓝底 + 深蓝字 + 字重 | 与 B 混用两套圆角 |
| **E. 只读元数据** | 卡片 tag、身份展示、搜索历史 | 小片展示；历史可点复用关键词 | 常显软蓝或描边片，无「选中机」 | 做成可删确认流 |

#### 5.4.1 A 类：词库多选详规

本仓库参考实现见附录 A 的 `skill-tag-picker`。

**表单区**

- 容器：浅底（`--c-surface-high` / `--c-bg` 软底），圆角 `--r-md`，最小高度约 88rpx，已选 tag 与 `+` 同行折行。
- 已选 tag：圆角 `--r-sm`，背景品牌软（`--c-blue-soft`），字色品牌深（`--c-blue-deep`），字号约 24rpx。
- `+`：虚线品牌边框方钮（约 56rpx），白底；点按打开抽屉。
- 点已选 tag → **Modal 确认后删除**（文案含标签名；确认色用危险红）。

**抽屉**

- `page-container` + `root-portal`，`position=bottom`，遮罩盖住原生顶栏。
- 默认高度约 **2/3 屏**（`66.67%`）；已选增多可升至约 80%+，须过渡。
- 结构自上而下：把手 → 标题「选择…」+「完成」→ 已选区（可滚）→ 搜索框 → 两列候选 `scroll-view`。
- 候选格：未选背景 **`--c-chip-muted`（中性灰，非美术蓝浅底）**；选中品牌软底 + 品牌字 + 字重 600；宽约 `calc(50% - gap/2)`。
- 筛选：本地字典过滤，输入防抖；无匹配给空态文案，勿当网络失败。
- 上限（如 12）超限 Toast，不静默丢弃。

**数据**

- 选项来自管理端字典 / 本地缓存；提交写回服务端（CSV 或数组按接口约定）。
- 设置页与资料编辑页必须同组件，禁止设置页退回「逗号分隔输入框」。

#### 5.4.2 B / C / D / E 速查

- **B**：热区高度优先 `--tap-min`；未选浅底、选中实心蓝是默认。筛选项少且同屏可见时不要抽屉。
- **C**：与 B 同壳，选中走软蓝而非实心/成功绿，避免「评价类型」与「服务标签」抢同一实心蓝语义时可：类型用实心，标签用软选。
- **D**：圆角用 `--r-md`，勿 `--r-pill`。
- **E**：字号可到 caption；收藏等语义可用警告软色，仍只读。

### 5.5 流程怎么走

每条流程只回答四件事：用户要完成什么、第一眼看见什么、做完怎么知道、失败往哪退。核心任务控制在 **3** 次点击内（预算，见第 1.5 节）。等待用第 6.1 节的时长档，按钮用第 2.8 节的五态。

| 流程 | 第一眼 | 主操作 | 成功 | 失败或放弃 | 禁止 |
|------|--------|--------|------|------------|------|
| **打开一页** | 标题或返回说明「这是哪」；有缓存先画出内容 | 本页唯一实心按钮，或列表本身可点 | 内容替换骨架，200ms 淡入 | 结构还在，给「点击刷新」 | 白屏超过 1s；把失败写成「暂无」 |
| **列表** | 第一项的主文，而不是筛选说明 | 点一行进详情。筛选用 chip，不超过 6 个 | 下拉刷新替换数据，位置尽量保持 | 保留旧列表，Toast 说没刷新成 | 清空再转圈；滑到底无限转圈。到底写「没有更多了」 |
| **AI 导购对话（修缮）** | 顶栏状态胶囊；空态引导卡（吉祥物 1:1）；底栏快捷 tag +「+」+ 输入；有字才出上箭头发送 | 发送为输入内圆形上箭头；参数只在下单前草稿卡（图/名/规格/地址/价/操作）；最近一张活卡一个实心「发布需求」或补缺项 | 命中后追加草稿快照；同一草稿旧卡灰蒙板写「草稿已更新」；确认发布后变状态条；支付/取消不在对话里完成；再来一单仅已完成且时间必重选 | 失败贴输入下，草稿保留；改自己一句截断其后 | 仍叫「搜索服务页」；微信绿；气泡复述全部字段；助手代付/代取消；过时卡可点 |
| **详情再行动** | 图、名称、价格（美术红）、一个主按钮 | 动词写结果：「预约」「加入购物车」 | 进入下一页或按钮进入结果态 | 留在详情，错误贴在按钮下 | 两个实心蓝；用一段文字教用户点按钮 |
| **表单** | 第一项字段名，不是一段介绍 | 页底一个提交。能选就不填 | 离开本页或明确写出已保存 | 留在表单，错误在字段下 **8pt**；已填内容还在 | 用 placeholder 当标题；提交失败整页替换成错误页 |
| **支付** | 应付金额与「付」按钮同时可见 | 只一个支付按钮。按下后进入按钮内加载 | 结果页或 Toast + 离开。可短震一次 | 留在支付前一屏，按钮回到默认，写明未扣成或待确认 | 连点两次下两单；用微信绿按钮 |
| **删除 / 不可逆** | 入口用危险红字，不要实心红铺满行 | 再弹一层确认，确认按钮写「删除××」 | 项消失，Toast 说明已删除 | 取消则什么都不发生 | 确认按钮只写「确定」；可恢复的操作也弹确认 |
| **登录 / 授权** | 说明要这个权限做什么（一句） | 一个主按钮走微信手机号或支付授权 | 回到触发登录的那一步，不丢已填内容 | 留在原页，给「再试一次」和「先看看」 | 未登录就展示「暂无订单」；授权按钮用微信绿抢品牌色 |
| **抽屉里选择** | 把手、标题、完成 | 点选项即选中；完成才关闭 | 表单上立刻看见已选 | 下滑或点遮罩关闭，未点完成则不写入 | 抽屉上再叠一层抽屉；选项超过一屏却不给搜索 |
| **离开已改表单** | 返回仍在左上，与胶囊对齐 | 点返回 | 没改过直接走 | 改过则确认「放弃修改」。确认后离开，取消则留下 | 静默丢掉已填内容 |

列表左滑只放删除或一个次操作，滑出宽度能点中（≥ 88rpx）。下拉只在页面顶部触发刷新，不在表单半截触发。

## 6. 弱网、空态与错误（通用）

移动端断网、弱网、切换基站是常态。预期应是「断了别吓人、有内容先看着、连上再刷新」，而不是「整页失败」。

| 情境 | 应有表现 | 禁止 |
|------|----------|------|
| 已有内容时刷新失败 | 保留内容；短暂提示 | 清空列表、全屏失败卡 |
| 首次进入且无缓存、请求失败 | 正常结构 + 可点重试（如「网络不太顺畅，点击刷新」） | 仅「加载失败」大门槛；失败画成「暂无数据」 |
| 轮询 / 自动刷新失败 | 静默跳过或低频提示 | 每次 Modal |
| 用户主动提交失败 | 提示 + 可留在当前页重试 | 整页错误页替代表单 |
| 缺参 / 非法入口 | 说明 + 返回路径 | 与网络失败混用文案 |
| 未满足前提（未选地址、未登录等） | 只引导补齐前提 | 同时展示「暂无结果」类否定结论 |
| 业务上确无数据 | 说明原因 + 下一步能做什么 | 「暂无」当整页结论、无出口 |

原则摘要：

1. 断网 = 中断本次更新，不是整页判死刑。  
2. 禁止全局失败 card 盖住本可继续浏览的布局。  
3. 可复用数据宜本地缓存：先铺缓存或骨架，再请求，成功写回。  
4. 缺参 ≠ 断网。  
5. **分态**：空数据、未满足前提、网络失败必须分开表达；失败用可点刷新，空态写清下一步，三者禁止共用一句「暂无」。  
6. 加载体验决定去留：弱网下友好的重试，往往能留住即将流失的用户。  
7. **同屏「暂无」只出现一句**：可选营销块（推荐、配套、可兑换、档位）没有数据时**整块不渲染**，不写成第二个「暂无」；账户数字（余额、可提现）为 0 仍显示 0。

### 6.1 加载指示按等待时长选

按下态在 100ms 内出现，用来满足多赫蒂的「收到了」（第 1.5 节）。转圈和骨架是另一件事：400ms 内能结束的不要加，免得闪一下。

不知道要多久：先只有按下态；满 **400ms** 仍未结束，再升级成按钮内加载或区域转圈；满 **3s** 若仍是整页且版式已知，再换成骨架。禁止第 0 秒就转圈。明知首屏要超过 1s 时，骨架在 **200ms** 内出现。结果尽量在 **2s** 内回来；到了 2s 加载指示必须已经在。

| 预计等待 | 用什么 | 用在 | 不用在 |
|----------|--------|------|--------|
| **&lt; 400ms** | 只有按下态 | 切 Tab、展开、读缓存、很快的提交 | 转圈、骨架、进度条 |
| **400ms～3s** | **按钮内加载** | 用户刚按下的提交、支付、保存 | 整页骨架 |
| **400ms～3s** | **转圈** | 一块区域：抽屉里的列表、下拉刷新 | 主按钮上再叠一个全屏转圈 |
| **&gt; 3s** | **骨架** | 首屏、列表、详情，版式已知。首屏骨架 200ms 内出现 | 进度未知的上传；骨架形状必须像最终内容，数据到了就停 |
| **&gt; 3s** | **进度条** | 上传、下载、分步生成等**进度可知** | 不知道百分比时假动一条到 90% 停住 |

按钮内加载的宽度不能变，避免整行跳动。微信原生 `button loading` 属性会在第 0ms 出圈：提交后先用标志位锁住重入，满 400ms 仍未返回再把 `loading` 置 true（见附录 A 的 `utils/btn_loading.js`）；按钮宽高与按下前相差 0。进度条旁写步骤（如 2/4）或百分比，二者有一个即可。局部加载不要换成全页错误。

## 7. 动效与反馈（通用）

时长只取三档。缓动默认 `cubic-bezier(0.22, 0.9, 0.32, 1)`（先快后慢）。用户打开「减少动效」时，骨架、入场、跑马灯停止，支付中的转圈保留。

| 档 | 时长 | 用于 |
|----|------|------|
| 按下 | **80ms** `ease-out` | 透明度落到 0.68，缩放 0.96；松手立即恢复 |
| 短过渡 | **120–200ms** | 底栏选中块 200ms；内容入场 180ms、透明度 140ms；离场 120ms，位移不超过屏宽的 14% |
| 状态 | **200ms** 淡入 | 内容显现。骨架闪动 1.2s 一轮，数据到达后停下 |

| 类型 | 标准 |
|------|------|
| Toast | 短结果与弱网提示；不替代业务校验 |
| Modal | 离开挽留、破坏确认、权限说明；不作网络失败主提示 |
| 下拉刷新 | 可开；失败不拆页 |
| 触觉 | 微信只有短震。仅支付完成、删除确认可震一次。普通点击、切 Tab 不震 |
| 禁止 | 长于 300ms 的界面转场、长时全屏动画、无意义骨架空转、网络失败全屏 Modal、自定义刺耳提示音 |

## 8. 内容与文案（通用）

- 标题说用户目标，不说内部模块名。  
- 按钮用动词。能用按钮或图标说清的，不再加说明句（第 1.4 节）。  
- 错误说下一步：缺什么、点哪里。字数尽量 ≤ 14 个字。  
- 金额格式全站统一，禁止各页私自拼接。价格用美术红，不在价格后再写「元人民币」一类解释。

## 9. 改 UI 前自检（通用）

1. 本屏主目标是否唯一？主按钮是否唯一醒目？  
2. 标题 / 返回 / 加载 / 异常出口是否齐全？  
3. 可读字是否 ≥ 28rpx？行高是否约 1.4～1.6？  
4. 热区是否够大？是否避开胶囊与安全区？  
5. 关键状态是否不只靠颜色？对比度是否达标？  
6. 断网是否只提示并保留内容？脏表单离开是否可确认？  
7. 是否引入了打断性弹层、装饰性炫技或与微信习惯冲突的隐喻？
8. 标签/chip 是否按第 5.4 节职责选用（词库多选 ≠ 枚举胶囊 ≠ 只读片）？
9. 首屏看起来是否仍是 6 主导（偏白或偏黑）: 3 辅助（蓝的层次）: 1 强调（一个重点）？是不是在用明度和饱和度拉开，而不是把蓝色铺满？
10. 价格是否用美术红、删除是否用危险红、成功是否避开微信绿？按下是否只改透明度而不换一套色？
11. 间距是否按 4 / 8 / 16 / 24pt 的关系在用（图标旁、组内、卡内、卡间距）？圆角是否按小元素 4～8、卡片 12、弹窗 16、胶囊 = 高度 / 2？
12. 按钮是否具备默认、按下、加载、禁用、结果五态？禁用是否写了原因？
13. 加载指示是否按等待时长选择（&lt;400ms 只有按下态，400ms～3s 转圈或按钮内，&gt;3s 骨架或进度条）？首屏骨架是否在 200ms 内出现？
14. 是否还写着控件本身已经表达的说明句？
15. 屏底主操作是否 ≥ 375rpx 宽、≥ 88rpx 高？同屏入口是否 ≤ 6、套餐是否 ≤ 3 档、一段表单是否 ≤ 5 个字段？
16. 若用了格式塔、新隐喻、峰终或孤立强调，是否准备了可用性测试，而不是只在自检里打勾？
17. 若用了第 10 节的转化模式：属于白区还是灰区？黑区是否出现？
18. 销量、在看、共同购买是否来自真实数据，并且达到本产品登记的最低展示数？未登记、未达、为 0 或没有数，是否整行不显示？库存、倒计时、划线价没有真实数时是否不显示？
19. 推荐区、进度条、券条是否挡住本屏唯一主按钮（屏底主操作宽仍 ≥ 375rpx）？

## 10. 商业转化模式（选用）

第 1.5 节约束尺寸与个数，第 1.6 节约束体验评估。本节是**可选用的商业转化目录**：基于心理机制触发行为，用本产品数据验证，按伦理分成白 / 灰 / 黑。不是每一页都要上营销；选用时仍遵守第 1～8 节（一个主按钮、希克选项上限、动效时长、玻璃用处）。

判断一句：做完之后用户是否觉得被帮到。觉得被骗的，不选用。

### 10.1 怎么验证

外部文章里的「客单价 +12%」「转化 +27%」只是别人测过的区间，**不是本产品验收指标**。上线用 A/B（或等价对照），只看本产品自己的数：

| 指标 | 用途 |
|------|------|
| 客单价、加购率、支付完成率 | 白区是否有效 |
| 弃购率、7 日留存、投诉数 | 灰区护栏：任一项相对对照变差，该模式下线，不靠再加紧迫感补 |

支付成功只用第 7 节已有的短反馈（Toast 或结果态，≤ 200ms 出现）。不加全屏礼花、不加长于 300ms 的庆祝动画。

### 10.2 白区（可直接选用）

服务用户目标；事后用户通常会感谢。每条含：机制、放在哪、界面约束、不许怎样。

| 模式 | 机制 | 放在哪 | 界面约束 | 不许 |
|------|------|--------|----------|------|
| **购物车交叉销售** | 购买动量；机会性曝光 | 购物车商品列表**下方**推荐区 | 删行后推荐随流式布局上移，**200ms** 内到位。结算条固定底，宽 ≥ **375rpx**，推荐不盖住结算。没有共同购买统计时，标题用「精选」等编辑推荐，不用「买了还买」 | 推荐做成第二个实心主按钮；推荐压住结算条；没有共同购买数据却写成别人也买了 |
| **免运费进度** | 损失厌恶；目标梯度 | 购物车或结算上方 | 文案「还差 ¥N 免运费」；N 用订单实算 | 没有运费规则仍显示；假门槛 |
| **锚定价格** | 锚定 | 商品详情价区；套餐三档 | 划线价须为该商品曾经真实标价。套餐 ≤ **3** 档（第 1.5 节希克）。中间档可标「常用」 | 虚构原价；预勾选高价附加项 |
| **推荐流** | 相关曝光 | 首页精选流、详情下方「相关」 | 只占次要位置；不取代本屏唯一实心主按钮 | 首屏堆满促销贴片挡住主 CTA |
| **合理默认** | 现状偏差 | 地址、手机号、上一单字段 | 可预填。付费项 / 订阅 / 加价服务**默认不勾选** | 默认勾选高价附加或自动续费 |
| **少填（特斯勒）** | 把操作转给系统 | 一键手机号、地址选择、带入上一单 | 步骤不增加；热区仍 ≥ **88rpx** | 用少填当借口隐藏必读协议 |
| **进度可恢复** | 沉没成本的正向用法 | 多步表单、草稿编辑页 | 离开须确认；草稿可留本机并恢复 | 文案写成「退出将清空」作威胁 |

### 10.3 灰区（可用，必须同时看护栏）

短期转化可能有效，但占用注意力或社交压力。上线后弃购率、7 日留存、投诉数相对对照**不得变差**；变差则下线。

| 模式 | 机制 | 放在哪 | 界面约束 | 不许 |
|------|------|--------|----------|------|
| **双方推荐奖励** | 互惠 | 邀请页、分享结果 | 双方利益与规则同一屏写清；拒绝按钮用中性文案 | 拒绝写成羞辱句；只奖励一方却写「双方」 |
| **业务进度提醒** | 动机 × 能力 × 提示 | 订阅消息：订单/任务进度、待办到达 | 用户可关；时机跟业务事件 | 用无限下拉或无意义推送刷打开次数 |
| **首单券** | 互惠 | 登录后、结算前 | 金额、门槛、到期日同一屏；到期前有一次提醒 | 试用结束无提醒静默扣款 |
| **真实销量 / 在看** | 社会认同 | 商品卡、详情 | 按**单个商品**判断。数字来自订单或在线统计，并且 ≥ 本产品为该证据登记的最低展示数。未登记、未达、为 0、接口失败：整行不渲染 | 伪造人数；写出「0」或「仅 1 人」这类未达阈值的数量 |
| **真实库存 / 截止** | 稀缺与紧迫 | 详情、活动页 | 与后台一致；到 0 或到点即停。倒计时只放**单个真实截止**处（如领券页）：剩余 > **24h** 只写日期，≤ 24h 才逐秒显示；到点停表并禁用；倒计时与日期不重复同屏 | 可重置的永久倒计时；假「仅剩 1 件」；长周期也每秒跳动制造虚假紧迫 |

### 10.4 黑区（禁止写入界面）

| 禁止 | 典型表现 |
|------|----------|
| 确认羞辱 | 拒绝按钮写成「不，我讨厌省钱」一类 |
| 蟑螂旅馆 | 开通一步、取消要多层或外呼才能停 |
| 无提醒自动扣费 | 试用结束静默扣款 |
| 伪装广告 | 广告或赞助装成普通内容卡 |
| 虚假稀缺 | 永久倒计时、假库存 |
| 干扰取消 | 取消订阅藏进三层以上菜单 |
| 诱导误确认 | 视觉诱导勾选高价附加项 |

### 10.5 同一机制的白 / 黑对照

| 机制 | 白区 | 黑区 |
|------|------|------|
| 损失厌恶 | 免运费进度（用户真实受益） | 「退出将丢失全部数据」威胁 |
| 社会认同 | 达到本产品登记阈值的真实已售 / 在看 | 未达阈值仍写出小数；伪造在看人数 |
| 默认效应 | 预填地址 | 预勾高价附加 |
| 稀缺 | 真实库存告急 | 永久倒计时 |
| 互惠 | 首单立减（规则透明） | 隐藏自动续费 |

### 10.6 数量型证据的展示阈值

已售、在看、共同购买都是数量型社会认同。用户把「别人已经买过或正在看」当成质量的代理。这个信号有阈值：低于某个量级时，真实的小数也会从正变负（负面社会认同）。写出「在看 2 人」或「已售 0」比不写更糟。冷启动只是这件事的另一面：信任资产还是零时，数量型证据还不能用。

规则：

- 按单个商品判断，不按「整个平台新不新」一刀切。同一个店里，达标的商品可以显示，未达标的不显示。
- 每种证据单独登记一个最低展示数。这个数来自本产品自己的弃购率、投诉数，不借用其他平台某个关键词下的销量分布。
- 未登记最低展示数时，该证据不展示。登记之后：计数 ≥ 最低数才渲染；低于、等于 0、或接口失败，整行不渲染。不写 0，不写「仅 N 人」。
- 未达阈值时，可以改用已经存在的非数量证据：认证、检测、售后承诺、真实图文。没有这些材料就留白。不为了填空去编销量或在看。
- 「买了还买」只在该商品有共同购买统计、且统计达到登记阈值时使用。否则推荐区用「精选」等编辑推荐标题。
- 伪造人数、刷出的订单数，按黑区处理。
- **账户资产不是社会认同**：积分余额、可提现等账户数字不套用本节阈值，为 0 仍显示 0（但绝不写「约等于 0」的引导语）。
- 券的「剩余 N 张」是**库存角标**（有真实 remaining 且 > 0 才显示，0 时按钮写已领完），不按已售阈值隐藏，也不冒充已售人数。

## A.1 多角色分包（大纳通式）

大纳小程序常按角色分包，而不是按业务复制一套 UI。命名可随模块调整，原则不变：

| 端（通称） | 典型根路径 | Tab / 壳 | 原则侧重 |
|------------|------------|----------|----------|
| C 端用户 | 主包 `pages/customer/*` | 2～5 Tab | 目标感、简洁 |
| 履约端 | `packageWorker` | 工作台自定义顶 + 子包 dock | 能动性（下一动作） |
| 经营端 | `packageSales` | 工作台自定义顶 + 页内 dock | 熟悉感（列表+详情） |
| 公共 | `packagePublic` | 无 Tab | 责任感（协议、钱包说明） |
| 代理端 | `packageAgent` | 工作台自定义顶 + 三栏 dock | 熟悉感（代理/消息/现场） |

跨端复用 `app.wxss` 组件类与 `nav_layout`。各业务的首屏目标对照写在该业务附录（修缮见 **B.1**）。平台联邦壳另有四身份分包，职责边界见 [平台联邦壳与订单生命周期.md](./系统设计/平台联邦壳与订单生命周期.md)。

冷启动**按本地角色直达**：端切换把角色写入本机（`mp_active_role`），下次启动 `role.restoreShellOnLaunch()` 加载对应分包后 `reLaunch` 工作台；新用户 / 无记录 / 分包未就绪一律落在 C 端首页，失败只 Toast 不阻断。

**代理例外**：进入「申请代理」**不**写入 `mp_active_role=agent`；冷启动仅当 `/api/v1/agent/me` 审批通过才恢复代理工作台，否则清回 `customer`。否则未通过用户每次打开会像「首页变成申请代理页」（工作台再 `redirectTo` 申请页）。排查：清 Storage 的 `mp_active_role`，或切回用户端。

## A.2 导航与顶栏实现

### A.2.1 壳顶栏、贴顶首页、二级浮顶

自定义顶栏（`navigationStyle: "custom"`）分三类。材质见第 4.5 节。不要把壳顶栏改成整条毛玻璃。

| 类型 | 用法 | 背景 | 样板 |
|------|------|------|------|
| **壳顶栏** `.ui-nav` | 可下滑的主壳 | **不透明** `var(--c-wash-top)`（经营端可用端洗色） | C 端主 Tab、各端 `workbench` |
| **贴顶首页** | 无 `.ui-nav`，头图贴顶；分类条用玻璃盖住头图底边 | 头图 + 第 4.5 节分类条 | C 端 `home` |
| **二级浮顶** `.ui-float-back` + `.ui-float-title` | 表单/详情 | 只做一个玻璃圆钮，不铺整条顶栏 | 多步流程、详情页 |

壳顶栏必须：

1. `position: sticky; top: 0; z-index: var(--z-nav)`（3，见第 2.6.4 节）。  
2. 禁止 `background: transparent`（真透明会让内容穿到状态栏下）。  
3. 与 `.shell-wash` 顶色一致，停顶时像「透明」，下滑时挡住内容。  
4. 未迁完的原生顶栏：`navigationBarBackgroundColor` / `backgroundColorTop` 与 `--c-wash-top`（或 `#c9daf0`）一致。
5. 次级工具页（支付、地址、设置、钱包、提现、学习、实名等）**保留原生标题**，不改自定义、不补圆形返回；只有主路径用第 2.7 节三类自定义顶栏。钱包类原生页只对齐顶栏颜色。

### A.2.2 圆形返回（`.ui-float-back`）

| 属性 | 规则 |
|------|------|
| 尺寸 | 与胶囊高度一致（`menuHeight`，至少 32px） |
| 垂直 | `top` = `menuTop` |
| 水平 | `left` = 右缘到胶囊右缘间距（`sidePad`，镜像） |
| 形态 | 正圆；内容仅为 `<`（`backMark`，勿在 WXML 裸写 `<`） |
| 层级 | `z-index: var(--z-back)`（4）；标题与返回同层且 `pointer-events: none`。页内抽屉用 3，返回恒高于抽屉 |

布局只来自 `utils/nav_layout.getNavLayout()`，禁止魔法数。

### A.2.3 返回行为

- 默认 `wx.navigateBack`；失败落到合理 Tab。  
- 脏表单：`form_guard` + `showModal`。  
- 「回主 Tab」类用 `switchTab`，语义写在 `bindtap` 名上。

### A.2.4 底栏

悬浮胶囊底栏：转场时底栏常驻；选中态用独立色块滑动。

| 端 | 实现 | 说明 |
|----|------|------|
| C 端 Tab | 原生 `tabBar` + `custom-tab-bar` | 文案路径包内固定，**不读后台**。本仓库现为**图标-only**：胶囊内只有图标（约 56rpx），顺序「我的 / 首页 / 商城」，选中靠 `--glass-pill` 滑块；热区仍整格 ≥ 88rpx。改顺序须同步 `tab_shell.syncTab` 的索引 |
| 履约端子包 | 单页壳 + `swiper` + dock | 子包不能挂原生 tabBar |
| 经营端 | 页内 dock + 壳工具 + `redirectTo`（L2） | 顶栏可保留「切换主体 / 回 C 端」 |

转场：

| 档 | 行为 | 适用 |
|----|------|------|
| **L1 游标式** | 底栏不动，内容水平滑动 | 履约端单壳 `swiper` |
| **L2 方向翻页** | 按 Tab 顺序自左/右入 | C 端 `switchTab` + `.shell-body`；经营端 `redirectTo` |

共享：`utils/tab_transition.js`。禁止用 `navigateTo` 做 Tab 切换；禁止底栏节点参与内容 `transform`。Linux 开发者工具路径上，履约端壳避免新增易触发 glass-easel 问题的自定义 `Component`，面板用 `swiper` + `include`。

### A.4.1 少量选择专有页（Peek 长图轮播）

**适用**：整页只做「在 2～4 个固定选项里选一个再进入」——选项集合小、稳定、彼此互斥，且选完立刻进入下一段流程或壳。**不是**列表筛选、表单字段枚举、可变长度资源列表。

**形态（硬性）**：

| 要素 | 约定 |
|------|------|
| 布局 | 自定义顶栏（`.ui-float-back` + `.ui-float-title`）+ 居中 `swiper` 竖版长图 + 底部主按钮 |
| Peek | `previous-margin` / `next-margin` 露出左右邻卡；当前卡 `scale(1)`，邻卡降透明度并略缩小 |
| 外框 | **不要**再套一层大圆角矩形/卡片壳；poster 自身圆角即可；`swiper-item` 背景透明 |
| 高度 | `swiper` **必须写死高度**（如 `calc(100vh - 280rpx)`），勿用百分比高度（易塌成 0） |
| 主按钮 | 叠在轮播下方，略上移与卡底软过渡（负 `margin-top` + 底边淡出），圆角胶囊 |
| 提示文案 | 按钮正下方浅灰小字，固定句式：「左右滑动选择{对象}，点击进入此{对象}」 |
| 未开通态 | 若选项需注册才可进：按钮改灰底灰字（`.muted`），文案改为「注册…」 |
| 运营图 | 管理端竖版槽位（建议 `1080×1920`）；库空用宿主回落图 |

**不适合本模式**（用列表 / chip / 表单分段）：选项数可变、表单内字段枚举、筛选条、双模式表单顶栏切换、选完仍停在本页的设置项。

新页自检：选项是否 ≤4 且集合固定？选完是否离开本页进入下一流程？若否，不要套 Peek 轮播。

业务样板与「已落地 / 不适合 / 候选」对照见 **附录 B.3**（更新修缮）。

## A.7 图片、图标与合法域名

运营图与图标公共读契约见 [媒体架构.md](./系统设计/媒体架构.md)（含 `ops/` 图床与 `icons/` 图标前缀）。部署核对表见 [`deploy/README.md`](../deploy/README.md)「小程序域名」。小程序后台「服务器域名」示例：

| 用途 | 类 | 域名 |
|------|----|------|
| 宿主 API | request | 业务域名（如 `dana.lobn.net`） |
| `wx.downloadFile`（图标缓存、主动下载） | downloadFile | 业务域 + `s3public.dana.lobn.net`（按实际下载主机） |
| 授权读预签名下载 | downloadFile | OSS endpoint 主机 |

**读链约定（防「模拟器有图、真机空白」）：**

1. 官方：`<image src>` **不**走 request/downloadFile 白名单；只有 `wx.downloadFile` 才校验 downloadFile。
2. 公开页设置把公共读图**改写为 ESA/s3public 直链**（Content-Length + CDN）；库内仍存 `/ops-media/…/file`。
3. `pageSettings.mediaUrl` / BFF **勿**默认 `proxy=1`（经 ESA 的宿主代理常变 chunked，真机 `<image>` 易裂）。
4. `home_static.isUsableRemoteImg`：放行 `/ops-media/` 与 `/ops/platform/`；勿按 `*_top_bar` 等物化种子文件名拒收。
5. `oss-image` 对 ops-media 不落盘 `downloadFile`；直链可缓存。

### A.7.1 运营照片（图床）

列表用 `thumb_url`；停稳后再换 `display_url`。实现：`components/oss-image`（骨架 + 本地文件缓存 + 缩略→渐进）。授权图禁止在客户端改 `x-oss-process`。

### A.7.2 图标（Lucide / SVG）

平台图标对象在公共读桶前缀 `icons/`（键名 `{name}__{variant}__{tone}.svg`），**不进** `OpsMediaAsset`，也**不走** `x-oss-process` / `oss-image` 渐进链路（那是照片规格）。

| 类别 | 落点 | 说明 |
|------|------|------|
| 壳层图标 | 包内 `assets/lucide` 精简集（约 50 个 SVG）+ `assets/tab` 等 | 搜索、底栏、我的页固定入口等首屏必现；不做成可配置 |
| 品牌 logo | 包内 `assets/brand/logo.jpeg` | 留在主包 |
| 分类宫格等可运营图标 | 远程 `icons/lucide/`（`bootstrap.icon_cdn_base`）+ `downloadFile` 本地缓存 | 种子在 `infrastructure/seed_icons`；白名单与 `lucide_icons` / `lucide_catalog` 对齐；失败骨架 |
| 分类自定义图 | 业务字段 `image_url`（图床）+ `oss-image` | 与 `icon`（Lucide 名）分开；有图走照片链路，无图才用 Lucide 名 |

本地文件缓存**只属于小程序**（无浏览器 HTTP 缓存可比拟）。Web 管理端继续用 `lucide-react` 现场上色；门户若展示同一枚图标，直接用 ESA 公共 URL。不注入整库 Lucide；种子只补传白名单，OSS 不可用则跳过。

## A.8 运行配置（`config/config.js`）

样板：`LOBN_DANA_UPDATE/miniprogram/WeChat/config/config.js`。  
本仓库为**原生小程序**（无 Taro / webpack 打包注入），运行配置写在 `config.js`，**不**在小程序根目录建 `.env`（微信运行时不会像 Node/Vite 自动加载；再加一层「编译写回」会与下方 `switch:*` 重复）。有打包器的工程可另议 `.env`。

### A.8.1 分两段：基础 / 高级

| 段 | 谁改 | 规则 |
|----|------|------|
| **基础配置** | 日常联调 / 发版必看 | 两项互不联动，各自填写 |
| **高级配置** | 默认全留空 | 均有默认值；**推荐不填**，仅排查或特殊部署时覆盖 |

每个变量在 `config.js` 内用块注释说明：**含义、控制什么 / 不控制什么、空值行为、常见取值**；勿只写示例 URL。`switch:*` 只改 `var name = ...;` 赋值行，保留注释。

### A.8.2 基础配置语义

| 变量 | 含义（控制什么） | 不控制 | 空值 | 常见取值 |
|------|------------------|--------|------|----------|
| `is_prod` | 客户端是否按生产行为：未填 `debug` 时关/开诊断、`envName`、发版心态 | **不**改写 `apiBaseUrl` | 视为 `true` | `true` 正式；`false` 本机联调 |
| `apiBaseUrl` | 宿主 REST 根（`wx.request` / 上传等）；`centralBaseUrl` 为空时鉴权也落此域；地图选点页拼接 | 不隐含「是否生产」 | **抛错**，须主动填 | 开发 `http://127.0.0.1:8000`；生产 `https://dana.lobn.net` |

场景对照：

| 场景 | `is_prod` | `apiBaseUrl` |
|------|-----------|--------------|
| 正式发版 | `true` | `https://dana.lobn.net` |
| 本机联调 | `false` | `http://127.0.0.1:8000` |
| 连生产查配置（配高级 `debug`） | `true` | `https://dana.lobn.net` |
| 生产行为 + 预发域名 | `true` | 预发完整 origin（须主动填） |

### A.8.3 高级配置语义

| 变量 | 含义 | 留空时默认 | 何时填写 |
|------|------|------------|----------|
| `debug` | 实人等页是否展示接口诊断（`identity/ready`、`ocr_reason`、刷脸 detail；**无密钥**） | `!is_prod` | 连生产排查时填 `true`（**勿提审**） |
| `iconCdnBase` | Lucide 公共读 CDN 根（无尾斜杠） | `/api/v1/mp/bootstrap` 写入；壳层仍用包内 | 极少；一般勿填 |
| `centralBaseUrl` | 中央鉴权根；可与业务 API 分域 | 与 `apiBaseUrl` 同域 | 鉴权与业务不在同一 origin 时 |

正式包发版前高级 `debug` 须留空或 `false`（或 `switch:prod`）。

### A.8.4 npm 切换（可选）

在对应 `WeChat/` 目录：

```bash
npm run switch:dev         # is_prod=false + 本机 apiBaseUrl；debug 留空 → 自动 true
npm run switch:prod        # is_prod=true + 生产 apiBaseUrl；高级 debug 留空
npm run switch:prod-debug  # 生产地址 + debug=true（仅排查）
```

脚本：`script.env.js`（只改赋值；同步 `project.config.json` 的 `appid` / `urlCheck`）。手改与脚本二选一；发版以 `switch:prod` 或等价手填为准。

### A.8.5 新模块落地检查

1. 是否只有 `config/config.js` 一处运行配置入口（无并行 `.env` / 第二套 baseUrl）？  
2. `apiBaseUrl` 是否显式非空？空是否在加载时失败而非静默回落？  
3. `is_prod` 是否未用来推导 URL？  
4. 高级段是否默认留空？生产包是否未长期打开 `debug`？  
5. `api.js` 等是否只读 `config` 导出，不散落魔法域名？

| 客户首页 | 发起预约或看进行中订单 | 主 CTA / 进行中订单卡 |
| 快捷下单 | 填意向 → 收报价 → 付定金 | 当前阶段与主按钮 |
| 服务 / 商品详情 | 理解服务并下单 | 图、价、主 CTA |
| 师傅工作台 | 报价 / 抢单 / 履约下一步 | 待办与主操作 |
| 订单详情 | 当前阶段下一动作 | 状态文案 + 唯一主按钮 |
| 销售工作台 | 线索与订单跟进 | 列表 + 当前主体 |
| 代理 · 代理栏 | 认出自己，进入主页 / 订单 / 代理费 / 纠纷 | 用户卡 + 订单卡；不出示码 |
| 代理 · 消息栏 | 在时间流里处理客户与订单 | 两种卡 + 顶部筛选胶囊 |

| 代理 · 二维码页 | 三秒出示分销码 | 码与分享主按钮 |

角色通称与包路径对应：客户 ≈ C 端用户；师傅 ≈ 履约端；销售 / 商家 ≈ 经营端；代理 ≈ `packageAgent`（见 A.1）。

## B.2 品类色（水 / 电 / 气）

品类色只给分类图标与只读 chip，**不进**主按钮、链接、底栏选中。变量仍写在 `app.wxss`，语义登记于此：

| 变量 | 映射 | 用法 |
|------|------|------|
| `--c-cat-water` / `--c-cat-water-soft` | 水 = 行动蓝家族 | 水类图标、只读 chip |
| `--c-cat-electric` / `--c-cat-electric-soft` | 电 = 警告色家族 | 电类图标、只读 chip |
| `--c-cat-gas` / `--c-cat-gas-soft` | 气 = 危险红家族 | 气类图标、只读 chip |

新增品类：先在本表登记再写变量；禁止页内临时 hex。其它业务线若有品类色，另立本业务附录，勿占用修缮语义。

## B.6 商业闭环样板（已落地）

本节是修缮按第 10 节落地的对照表：能力 → 位置 → 界面约束。灰区项上线后按第 10.1 节盯弃购率、7 日留存、投诉数；变差即下线。发放与分成算法（`claim_coupon`、`points_ledger.spend`、`snap_order_commission`、成交中位与目录倍率）不改。

| 能力 | 位置（相对 `WeChat/`） | 界面约束 | 规范位置 |
|------|------------------------|----------|----------|
| 参考价来源行 | `pages/customer/product-detail` 价格抽屉 | 抽屉写明来源：样本达标写「近 N 日成交中位（k 单）」，否则「目录参考价」；样本 0 保持「还没有成交记录」，不写 ¥0。划线原价只用 `original_price` / `list_price` 真实高于现价时出现，**不用 `market_price` 合成** | 10.2 锚定 |
| 券规则同屏 | `pages/customer/coupons`、`packagePublic/coupon-claim` | 金额（唯一美术红）、门槛、有效期、所需积分、每人限领同一张卡；规则行**有值才渲染**；状态角标只留一个 | 10.3 首单券 |
| 领券页倒计时 | `packagePublic/coupon-claim` | 全站唯一逐秒倒计时位：`ends_at` ≤ 24h 才显示，> 24h 只写日期；到点停表并禁用；已领取 / 已结束 / 已领完为终态，按钮唯一文案且不再叠倒计时与剩余角标 | 10.3 真实截止 |
| 积分可兑换 | `pages/customer/points` | 只列 `points_cost > 0` 的券；行高 88rpx、无实心按钮，点整行进领券页；0 张整节不渲染。余额卡纸色、64rpx 墨色数字，为 0 仍显示 0 | 6 / 10.2 |
| 分成权重只读 | `packagePublic/referrals`、`packageWorker/referrals` | **有代理席位才渲染**四行「省 / 市 / 区 / 街道站长 + 权重」；当前级别蓝软底、行不可点、不画进度条；客户邀请页 `promo` 不放此块 | 10.3 双方奖励 |

师傅与商家端看见同一套市场价用于报价；行情数字用美术红，不与客户抢同一颗实心蓝主按钮。
