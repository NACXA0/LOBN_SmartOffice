# 管理端页面设计规范

本文约定 **LOBN_FireClassroom React 管理后台**（`/admin/`）的壳层与页面信息架构。小程序规范见 [小程序设计规范.md](小程序设计规范.md)，二者**不要混用布局隐喻**。

产品权限与「平台端 / 门店端」语义以子仓为准：

→ [LOBN_FireClassroom/docs/角色与控制台.md](../LOBN_FireClassroom/docs/角色与控制台.md)  
→ [LOBN_FireClassroom/docs/管理端.md](../LOBN_FireClassroom/docs/管理端.md)

## 1. 壳层

- 左侧栏为唯一主导航；顶区是**控制台切换**，不是装饰性店招。
- **平台端**：无「当前门店」；顶区写清「平台管理员」。下拉用于**进入**某店某身份。
- **门店端**：顶区为「店名 · 身份」；下拉切换门店或（管理员）回到平台端。
- 退出登录放在侧栏底部，不塞进顶区下拉。

## 2. 一页一事

- 页头：标题 + 至多一句职责说明；不写实现备注、设计对照、与标题重复的眉题。
- 列表页：工具条（搜索 / 分段 / 排序 / 刷新）→ 表 → 分页。
- 危险操作：确认对话框；需输入「确认」的场景保持一致。

## 3. 人员与门店

- 管理员与门店身份**分开展示**：配置来的 `admin_phones` 不进「店·角色」行。
- 名册 → 抽屉速览 → 带 id 的档案路由。
- 私人备注仅当前登录人可见。

## 4. 视觉底线

- 沿用 `frontend_admin` 既有 CSS 变量与组件（`Button` / `Card` / `PageHeader` 等），不另起一套主题。
- 避免把小程序自定义 tabBar、胶囊对齐规则搬进 Web 管理端。
- 平台端可用轻微强调色区分「管理员端」顶区，但不要做成营销着陆页。

## 5. 改文档时

壳层或 RBAC 变更时，同步改子仓 `docs/角色与控制台.md`、`docs/管理端.md` 与本页第 1～3 节。
